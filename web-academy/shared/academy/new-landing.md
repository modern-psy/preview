# Новый лендинг из компонентов Academy

Это библиотека исходников внутри репозитория Web Academy. Начинать новый
лендинг можно с существующих компонентов, подключая их из `shared/academy/`.
Новый проект не должен импортировать CSS, JavaScript или данные другого курса.
Для Hero с текстом слева и объектом фотографии справа применять общий вариант
`image.composition: "subject-right"` по [контракту Hero](hero.md#медиа-состояния-и-tilda).
На адаптивах главный объект должен оставаться видимым и смещаться к центру кадра;
проверять фото на каждой ширине, а не копировать координаты соседнего курса.

Каталог и контракты — [README.md](README.md). Состояние извлечения эталонного
лендинга и оставшиеся зависимости —
[COMPONENTS.md «Психолога-консультанта»](../../projects/psychologist-consultant/COMPONENTS.md#готовность-к-переиспользованию).
Правила — [components.md](../../rules/engineering/components.md).

## Начало работы

1. Создать `projects/<slug>/` с собственными `AGENTS.md`, `README.md`,
   `COMPONENTS.md`, `index.html`, `styles.css`, `data/` и `assets/`.
   `STATE.md` нужен только для текущего незавершённого действия или препятствия.
2. Сопоставить секции нового макета с каталогом. Сначала выбирать готовую
   целую секцию; карточки и другие вложенные компоненты уже входят в неё.
3. Прочитать [систему отступов и проверки Figma](spacing.md),
   [единый контракт адаптивов](responsive.md) и подключить
   [общие токены карточек](card-spacing.md). Прочитать руководство каждого выбранного блока: обязательные CSS/JS,
   варианты, поля данных, ограничения композиции и порядок подключения.
4. Подготовить собственные тексты, изображения, ссылки и тему. Примеры старого
   курса показывают структуру данных; даты, цены, состав преподавателей,
   отзывы, лицензия, получатели формы и popup hooks не переносятся автоматически.
5. Запустить локальный сервер и Browser до визуальных изменений, собрать
   страницу, сверить с новым Figma и проверить адаптивы и состояния.

В новом проекте сохранять обычные HTML/CSS/JS. React, Tailwind и npm-пакет
для использования этой библиотеки не нужны. Node выполняет `.mjs` при локальной
генерации; посетитель сайта получает готовый HTML.

## Генерация разметки

**Renderer + данные.** Для Hero, CTA, recognition, ratings, practice-path,
foundation, program, learning-timeline, trial-lectures, support-team, teachers,
diploma, graduation, lead-form, reviews, pricing, admission, academy-showcase и FAQ использовать соответствующий shared `*-render.mjs`.
Сигнатуры различаются: читать контракт конкретного компонента. Например:

```js
// Фрагмент projects/<slug>/render-page.mjs
import fs from 'node:fs/promises';
import {renderFaq} from '../../shared/academy/faq-render.mjs';

const data = JSON.parse(await fs.readFile(
  new URL('./data/faq.json', import.meta.url), 'utf8'
));
const faqHtml = renderFaq(data, {id: 'faq'});
// Вставить faqHtml в область faq:start/end своего index.html.
```

Минимальные данные этого примера:

```json
{
  "heading": "Вопросы о программе",
  "items": [
    {"question": "Как проходит обучение?", "answer": ["Подтверждённый текст нового курса."]}
  ]
}
```

Точка интеграции обновляет только свою маркированную область, проверяет наличие
одной пары маркеров и не переписывает остальную страницу. Пример механизма —
[render-support-team.mjs](../../projects/psychologist-consultant/render-support-team.mjs).
Вызывать адаптер нового проекта; импорт адаптера старого курса изменит старый
`index.html`. Generated-разметку после подключения renderer вручную не править.

Hero принимает свои данные и реестры assets/actions; весь вложенный состав
создаёт [hero-render.mjs](hero-render.mjs). Для преподавателей состав хранится
в отдельном редактируемом HTML-модуле с JSON по [teachers.md](teachers.md).
Другим блокам не навязывать этот формат, если их контракт использует обычный JSON.

**Финальные секции.** [Форма](lead-form.md), [диплом](diploma.md) и
[блок после выпуска](graduation.md) имеют полные shared renderer и JSON API.
Использовать их с собственными данными и уникальными ID; для формы обязательно
составить project form contract и инструкцию настройки нативного блока Tilda.

## Подключение и тема

Общий корень страницы:

```html
<main class="main-wrapper academy-page new-course-page" data-academy-anchor-scroll>
  <!-- Секции нового лендинга с уникальными ID -->
</main>
```

`new-course-page` заменить собственным классом. В `styles.css` этого класса
задать тему, поля страницы, ширины внешних контейнеров и необходимые публичные
токены. Внутренние сетки, типографику и состояния брать из библиотеки.
Не подключать `projects/psychologist-consultant/styles.css`: там остались
настройки конкретного лендинга.

Перенос поведения включает настройки темы: соблюдать
[правила переиспользования Shared](reuse-rules.md).
Не задавать заново длительности и easing готовых компонентов; сохранять
утверждённый сценарий и документировать его обязательные токены.

Для FAQ из примера нужны `components.css`, `section-spacing.css`,
`body-text.css`, `toggle-icon.css`, `faq-responsive.css`, `section-heading.css`
и тема страницы. В исходном HTML пути вида `../../shared/academy/faq-responsive.css`
корректны, если сервер запущен из корня репозитория. Заголовки подключать после
стилей потребляющих компонентов, тему — с учётом контракта их публичных токенов.
Шрифт подключить отдельно; его имя задаёт `--font-family-body`.

`components.js` подключить один раз для FAQ/CTA/общего управления слайдерами.
Якоря требуют `anchor-scroll.css` и `anchor-scroll.js`. Остальные JS-модули
подключать только по выбранным блокам. Преподавателям и отзывам нужен Splide
4.1.4; форме — intl-tel-input 29.1.2 перед `lead-form.js`. Полный порядок
зависимостей указан в руководствах компонентов.

Для нового лендинга не наследовать неявно ограничения внешних колонок,
максимальную ширину тарифов или настройки цвета Tilda из старого `styles.css`.
Если нужен новый общий вариант, добавить его в shared-компонент и проверить
существующих потребителей. Изменение shared исходников отражается на локальных
лендингах сразу; уже вставленная в Tilda версия изменится только после пересборки
и замены её фрагментов.

## Сборка и передача

Универсальной команды создания и сборки произвольного лендинга пока нет.
`projects/psychologist-consultant/build-tilda-bundle.mjs` — пример интеграции,
а не готовый сборщик для любого slug: он использует конкретные файлы, ID,
ассеты и модули этого курса. В новом проекте нужен собственный адаптер сборки
под выбранный состав секций, без копий общих CSS/JS.

Сборщик должен встроить общие исходники, обработать локальные изображения,
сохранить порядок зависимостей и создать автономные HEAD, STYLE, BODY и FOOTER.
Перед разбиением проверять CSS/JS через `assertResponsiveContract` из
`responsive.mjs`, а каждый CSS, включая тему, — через `assertMotionContract`
из `motion-contract.mjs`. Каждый файл — меньше 65 000 символов; разбиение сохраняет целые правила CSS,
секции и JS-модули. Порядок переноса и hashes записываются в manifest и инструкцию.
В итоговом Tilda HTML не остаются ссылки на `shared/` или файлы репозитория.
ZIP старого курса — готовая страница с его содержимым, не источник компонентов.

До передачи применить обязательный
[стандарт Tilda delivery](../../rules/engineering/tilda-delivery.md): одна секция
на нумерованный BODY/T123, русский комментарий в начале, нулевые внешние поля
T123, `min-height: 0; height: auto` на каждом экспортном wrapper, один владелец
section spacing, непересекающиеся scroll ID и popup hash, page-scoped authored
classes и обязательные build/live release gates.

Форма требует собственного `data/form-contract.json`, native marker и
настроенного нативного блока на новой странице Tilda по [lead-form.md](lead-form.md).
Marker нельзя наследовать из проекта-примера: его задают в native block текущей
страницы, подтверждают в опубликованном DOM и только затем фиксируют в JSON.

Проверить новый контент на 375/768/1024/1440px и границах используемых адаптивов,
длинные тексты, изображения, focus/hover, клавиатуру, no-JS, reduced motion,
ошибки и точный перенос собранных фрагментов. Наличие файла в shared не заменяет
визуальную приёмку нового лендинга. Публикация вне Tilda требует отдельного
разрешения для нового проекта; разрешение на старое командное превью не переносится.

## Поручение для следующего рабочего чата

> Создай лендинг «Название» в `projects/<slug>/` по этим макетам Figma.
> Используй библиотеку `shared/academy/` и руководство `new-landing.md`.
> «Психолог-консультант» используй как пример интеграции. Подключай готовые
> секции и вложенные компоненты, сохраняя общий CSS/JS. Контент, ассеты, ссылки
> и тему нового курса храни отдельно. Перед работой проверь оставшиеся
> зависимости в его COMPONENTS.md. Собери и проверь автономный комплект Tilda.
