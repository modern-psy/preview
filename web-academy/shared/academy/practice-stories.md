# Истории изменений в практике

Составной компонент: `renderPracticeStories(data, {id})`,
`practice-stories.css`, `practice-stories.js` → `<academy-practice-stories>`.
Первый потребитель — КПТ Оксфорд, Figma `31:2177`.

## Владение

- Лендинг: `heading`, `description`, массив `items` с уникальными `id`,
  `name`, `quote`, `lead`, `caption`, постоянным HTTPS `image`, `width`, `height`, `alt`.
  Порядок карточек и кадрирование (`position`) принадлежат лендингу.
- Shared: композиция заголовка, лента, адаптивы, закрепление при прокрутке,
  размеры карточек и типографика. Карточка — `renderReviewCard`, `type: 'quote'`,
  `responsive: true`. Полная история видна в цитате и подписи; раскрытия нет.
- Контрастная секция использует `section-spacing_component.is-inset` со своей
  шкалой `--section-inset-space`: сверху и снизу 60px до 520px, 80px на
  521–767px, 100px на 768–1024px. От 1025px нижнее поле остаётся 120px,
  а верхнее поле `--practice-stories-inset-top` равно 100px, чтобы имя и
  описание помещались в закреплённом viewport. Значения заданы в rem.
  Поля утверждены пользователем для этой секции 2026-09-16; шкала тарифов остаётся прежней.
  Заголовок, описание и расстояние до ленты — общие `section-heading`
  и `section-layout`. Горизонтальные поля следуют `--page-padding` и
  `--container-xlarge`, в том числе после последней карточки.
- Тема: `--color-surface-dark`, `--color-text-on-dark`,
  `--color-text-on-dark-muted`; `--practice-stories-muted` задаёт вторую
  часть подписи. Панель цитаты сохраняет общий фон отзывов.

## Поток данных и рендеринг

`renderPracticeStories` выполняется при сборке, проверяет обязательные поля,
уникальность ID и HTTPS-метаданные изображений, затем создаёт семантические
`section` → `ul` → `li`. Каждая `li` получает готовую
`renderReviewCard({...item, type: 'quote'}, id, {responsive: true})`; имя
не смешивается с описанием и остаётся отдельным заголовком карточки. Данные и
порядок не читаются из DOM и не меняются runtime-кодом.

`<academy-practice-stories>` отвечает только за progressive enhancement ленты:
измерение, включение подходящего режима прокрутки, клавиатуру и cleanup. Если
Custom Elements, ResizeObserver или JavaScript недоступны, весь список, цитаты,
имена и результаты уже присутствуют в HTML. Сборщик Tilda встраивает результат
renderer, CSS и runtime; браузер не загружает исходные файлы из `shared/`.

## Адаптивы и поведение

Имя студентки выводится над результатом как `content-heading_component.is-card`
в общей группе `content-header_component`; оно белое через роль caption color.
Gap имени и описания совпадает с группой копирайта карточки преподавателя:
8px на мобильных, 12px от планшета. Ширина карточек в горизонтальном ряду поступает из `review-list_component.is-responsive`:
тот же `--review-slide-width`, что у Reviews. Внутренние поля, высота медиа,
кегль, радиус и расстояние до подписи — из `review-card` и
`reviews-responsive`. В закреплённой композиции JS измеряет самый высокий блок
имени и описания и отдаёт всем карточкам одну высоту медиа из оставшегося места
viewport. Поэтому фотографии всегда равны, полный текст сохраняет естественную
высоту, а под более короткими описаниями может оставаться больше свободного
места. Фиксированной desktop-высоты фото у секции нет; значение пересчитывается
при изменении размеров.

От 768px с точным указателем и hover ряд движется влево по мере
вертикальной прокрутки страницы: посетитель последовательно видит истории
справа. Поведение основано на `dialogue` из «А что, если стать психологом?».
Колесо/жесты страницы не перехватываются. Движение — `transform` через RAF.
Если заголовок и карточки не помещаются по высоте, закрепление отключается.
Внешние вертикальные поля сохраняются. Закрепление начинается по верхней
границе тёмной секции (`top: 0`), а не по положению заголовка: увеличенный
верхний inset остаётся видимым и даёт clearance фиксированному хедеру.
Закрепляемый контейнер имеет высоту viewport; если карточки выходят ниже,
их переполнение добавляется к длине секции и спокойно выходит перед следующим
блоком, не меняя точку фиксации верхней границы.

До 768px закрепления и горизонтального скролла нет. До 520px карточки стоят
вертикально, их ширина дополнительно ограничена 368px с выравниванием по центру.
Диапазон 521–767px, который Tilda использует для горизонтальных телефонов,
всегда образует две равные колонки с gap 16px; CSS `orientation` намеренно не
используется, потому что предпросмотр Tilda сообщает его ненадёжно. Пятая
карточка занимает ширину одной колонки и центрируется под ними.
На широких touch-экранах и при reduced motion — нативная горизонтальная лента
без связи с вертикальным скроллом. Без JS сохраняются эти же адаптивные раскладки.
Горизонтальная область доступна по Tab; стрелки
влево/вправо, Home/End перемещают ленту, в закреплённом режиме синхронизируя
вертикальную позицию. Вертикальный список не добавляет остановку Tab.
Есть видимый focus. Скролл страницы не блокируется.

Регистрация однократная; disconnect освобождает ResizeObserver, listeners и
RAF, reconnect восстанавливает поведение. Инстансы независимы. Основа lifecycle —
[MDN Custom Elements](https://developer.mozilla.org/en-US/docs/Web/API/Web_components/Using_custom_elements),
пересчёт геометрии — [ResizeObserver](https://developer.mozilla.org/en-US/docs/Web/API/ResizeObserver).

## Подключение и Tilda

CSS: `components.css`, `card-spacing.css`, `review-card.css`, `review-panel.css`,
`reviews-responsive.css`, `practice-stories.css`, `section-spacing.css`;
`section-heading.css` после CSS потребителей. JS: только `practice-stories.js`
в FOOTER/defer. Splide, `review-card.js`, `review-panel.js` не нужны для коротких
статичных цитат. Они остаются зависимостями обычных раскрывающихся отзывов.

Сборщик встраивает CSS/JS, фотографии остаются на постоянных CDN URL.
Не подключать `shared/` по относительным путям в Tilda.
Renderer: `node --test shared/academy/tests/practice-stories.test.mjs`.
