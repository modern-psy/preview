# Тарифы Academy

Цельный opt-in компонент: [pricing.css](pricing.css), [pricing.js](pricing.js),
build-time [pricing-render.mjs](pricing-render.mjs). Подключать после
`components.css`, вместе с `body-text.css`, `button.css` и `section-heading.css`, перед темой. Первый consumer —
`projects/psychologist-consultant/`, по прямому поручению сделать компонент общим.

## Владение

`academy-pricing.pricing_component` владеет всей композицией: переключателями
потоков, заголовочной группой, карточками цен, плашкой популярности, кнопками,
списками, адаптивом, состояниями и анимациями. Не копировать эти CSS/JS в лендинги.
H2/подзаголовок — `section-header_component`, `section-title_component` и
`section-subtitle_component`; названия тарифов — `content-heading_component.is-prominent`
в `content-header_component`. Размеры и интервалы заголовков задаются через токены общего API.
Описания — Body Text `is-summary is-regular is-statement`; условия оплаты —
`is-caption is-regular is-statement`; список — обычный Body Text с весом 400
и верхним пределом 18px.

Лендинг владеет внешней секцией, шириной контейнера, copy, ценами, датами,
иконками и действием. Его JSON передаётся `renderPricing(config)` при сборке.
Результат — полный semantic HTML, без runtime fetch, фреймворка или зависимости
от Node в Tilda. `id` должен быть уникальным на странице.

## Данные и public API

- `streams`: один или два объекта `{id, label, start}`. Один поток автоматически
  скрывает табы. Два показывают переключатели после готовности JS.
- `plans`: один–три объекта `{id, name, description, featured, badge?, prices,
  action, actionLabel, href, tildaManaged?, features}`. `prices[streamId]` — независимые
  `{monthly, total, months, monthlyPrefix?}` (например, `monthlyPrefix: "от"`); `null` означает явно неподтверждённую стоимость.
- Один тариф получает `pricing_grid.is-single`: по центру, ширина до
  `--pricing-single-max-width` (по умолчанию 31rem). Название ограничено
  `--pricing-name-max-width` (19.375rem в этом варианте). Остальные раскладки не меняются.
- `features`: `{text, included, highlighted?}`. Обычные включённые пункты используют
  `icons.check`, отсутствующие — `icons.cross`, дополнительные — `icons.highlight`.
  Для отсутствующего пункта есть доступный текст «Не входит», а не только цвет.
- `icons`: точные URL `check`, `cross`, `highlight`, `flame`. Intrinsic размеры изображений — 18×18; CSS отображает их
  как 16×16px до 520px по уточнению пользователя, 18×18px выше. `alt=""`, `aria-hidden`, `draggable="false"`.
- `href` задаёт настоящее действие; без назначения — preview button с
  `aria-disabled`, pointer и видимым focus. Компонент не отправляет формы.
  Для popup alias Tilda задать `tildaManaged: true`; ссылка получит
  `data-tilda-popup-link` и не будет перехвачена anchor-scroll.
- Атрибут `selected-stream` — единственный источник выбранного потока.
  Неизвестное значение нормализуется к первому потоку.
- `academy-pricing:change` — всплывающее событие с `detail.stream`, один раз
  на фактическую смену выбора; повторный выбор события не создаёт.
- Hooks: `data-pricing-tabs`, `data-pricing-tab`, `data-pricing-panel`,
  `data-pricing-stream`, `data-pricing-order`, `data-pricing-featured`.
  `data-ready` принадлежит lifecycle и не устанавливается вручную.

## Визуальные и адаптивные правила

- Цвет заголовочной группы наследуется от поверхности: `--pricing-text`,
  по умолчанию Academy `--color-text-on-dark-muted` (`#e6e5eb`).
- Основные темы: `--pricing-surface`, `--pricing-card-top`,
  `--pricing-featured-top`, `--pricing-muted`, `--pricing-excluded`,
  `--pricing-tabs-surface`, `--pricing-tab-active`.
- Hover только `.pricing_card` гасит opacity её градиентного pseudo-element:
  остаётся верхний цвет этой карточки. Hover кнопки, списка или оболочки
  популярности не гасит градиент. На coarse/touch этот эффект отключён.
- Табы меняют **только цвета** фона и текста: никакой сдвигающейся подложки.
  Переходы берутся из `--transition-site`; fade даты/цен — из общих
  `--motion-duration` (миллисекунды) и `--motion-easing`. Без токенов fallback —
  **250ms linear**; в «Психологе-консультанте» действуют проектные **150ms ease-in-out**.
- До 767px тарифы расположены вертикально, популярный — первым. Компонент
  переставляет реальные DOM-узлы: визуальный, читаемый и клавиатурный порядок совпадают.
  Высота карточки свободная, между текстовой группой и ценой `gap: 3rem` (48px по новым мобильным макетам).
- От 768px восстанавливается порядок `plans` из JSON; одинаковые доли колонок.
  Для трёх тарифов на планшете две колонки и третий по центру, от 1025px — три.
  Вложенные [CSS subgrid](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout/Subgrid)
  выравнивают верхние карточки по самой высокой в ряду: кнопки и начало списков
  всегда стоят на одной горизонтали, без JS-измерения и фиксированной высоты.
- Планшет 768–1024px: minimum карточки 17rem (поправка пользователя вместо 25rem),
  контент может увеличить высоту; боковые padding таба 1.25rem.
- До 767px padding оболочки табов 0.125rem, таба 0.25rem 0.75rem;
  высота кликабельного таба сохраняется не меньше 44px.
- Заголовочная группа → карточки использует только общий `section-layout_component`.

На мобильных gap между планами — 28/32px, между пунктами — 4/8px.
Плашка популярности: поля 8px и gap 8px до desktop, 10px сверху и gap 10px
на desktop. Геометрия основных кнопок и межсекционный ритм остаются общими.
Сохраняются предыдущие утверждённые поправки: minimum 17rem на планшете,
20px боковые поля планшетного таба, компактная мобильная оболочка табов 2px,
44px интерактивные цели, контраст отсутствующих пунктов `#99929f`.
Цены зимнего потока берутся из данных лендинга; Figma не сбрасывает их к осенним.
Названия потоков всегда остаются в одну строку. Равные grid-колонки учитывают
max-content самого длинного названия; при увеличенном тексте и нехватке места
прокручивается только переключатель, без переполнения страницы. Суммы могут
переноситься. Focus outline таба рисуется внутри, чтобы scroller его не обрезал.

В `title` можно задать явный перевод строки (`\n`): renderer безопасно экранирует
каждую строку и создаёт `<br>`. Это настройка данных конкретного лендинга;
обычный заголовок без перевода строки сохраняет прежний вывод.

## Доступность и lifecycle

Семантика [WAI-ARIA Tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/):
Left/Right, Home/End перемещают focus и выбирают поток; Tab уходит из tablist
в общую переиспользуемую panel. `aria-selected`, `tabindex` и `aria-labelledby`
синхронизированы с атрибутом. Неактивные даты/цены имеют `hidden`.

Без JS видны все потоки и цены с подписями; неработающие табы скрыты, популярный
тариф идёт первым. При reduced motion смена состояния мгновенная. Reconnect
сохраняет выбранный поток, освобождает/восстанавливает listeners и media queries.
Повторная загрузка скрипта не регистрирует Custom Element повторно.
Несколько компонентов независимы; вложенные экземпляры не поддерживаются.

HEAD: встроить CSS. BODY: результат renderer с уникальными ID. FOOTER:
встроить `pricing.js` один раз. JSON, renderer и локальные shared URL не нужны
в runtime. Пример данных — `projects/psychologist-consultant/data/pricing.json`;
проверочный генератор — `projects/psychologist-consultant/tests/build-pricing-fixture.mjs`.

Дата старта потока использует общую вводную шкалу 16/18/20/22px:
на tablet 768–1024px — 20px, по уточнению пользователя.

Радиус обычной карточки/медиа следует `--radius-card`: 12px до 767px,
16px от 768px. Подключать [card-spacing.css](card-spacing.css) после базового
`components.css`, включая самостоятельный экспорт компонента.

Обычная текстовая шапка использует `section-header_component.is-responsive`: отступ
заголовок → подзаголовок 20/20/24/28px из [spacing.md](spacing.md), без
компактного portrait-исключения.
