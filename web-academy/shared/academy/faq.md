# FAQ Academy

Готовый компонент блока вопросов и ответов: заголовок, пояснение/поддержка,
список вопросов, ответы, интерактивная иконка и анимации раскрытия.
Использовать его в новых лендингах вместо отдельной реализации FAQ.

## Исходники

| Файл | Содержимое |
| --- | --- |
| [faq.html](faq.html) | Готовый шаблон разметки |
| [components.css](components.css) | `faq_*` и базовые `accordion_*`: оформление и CSS-состояния |
| [components.js](components.js) | Единый обработчик `data-accordion*`, анимации и cleanup |
| [tests/faq-fixture.html](tests/faq-fixture.html) | Стенд состояний и нескольких экземпляров |

FAQ — композиция общего accordion. Отдельный второй `faq.js` не нужен:
одновременное подключение двух обработчиков создаст двойное переключение.
Текущие лендинги `psychologist-consultant` и `trauma-therapy` уже используют
эту реализацию; исходники не нужно заново копировать из этих проектов.

## Подключение

1. Подключить `components.css` и `components.js` один раз на страницу.
2. Вставить `faq.html` внутри `.academy-page` и контейнера лендинга. Внешние
   отступы и ширина колонок принадлежат секции проекта; типичный вариант —
   центральные 10/12 колонок `column-grid_content.is-content-wide`.
3. Заменить вопросы, ответы, описание и ID заголовка. Если есть ссылка
   поддержки, её адрес задаёт проект. Данные другого курса не наследуются.
4. Сохранить классы и hooks из шаблона. `data-accordion-single` означает
   один открытый ответ в группе. Удалить только этот атрибут, чтобы разрешить
   несколько открытых ответов.
5. По умолчанию все ответы закрыты. Для открытого начального ответа добавить
   нативный `open` к нужному `details`; в single-режиме задавать не больше одного.

```html
<link rel="stylesheet" href="../../shared/academy/components.css">
<script src="../../shared/academy/components.js" defer></script>
```

Дополнительные библиотеки, изображения и отдельные обработчики кликов не нужны.
Иконка плюс/крест построена общими CSS-псевдоэлементами.

## Публичная разметка

- `faq_component` → `faq_header` (`faq_heading`, `faq_support`) + `faq_list`;
- список: `faq_list accordion_component` с `data-accordion`;
- пункт: нативный `details.faq_item.accordion_item` с `data-accordion-item`;
- вопрос: `summary.faq_question.accordion_summary` с `data-accordion-trigger`;
- внутри вопроса: заголовок `faq_question-heading` и декоративный
  `span.accordion_icon[aria-hidden="true"]`;
- ответ: `faq_answer accordion_panel` с `data-accordion-panel`, затем
  `faq_answer-inner accordion_panel-inner` и семантический контент.

Порядок H2/H3 адаптировать к странице, сохранив логическую иерархию.
Не заменять `summary` на `div` и не вкладывать в него кнопки или ссылки.
Ссылки внутри ответа работают самостоятельно. ID должны быть уникальными;
несколько FAQ-групп внутри `.academy-page` управляются независимо.
Не вкладывать одну `data-accordion`-группу в другую.

## Состояния и анимации

| Состояние | Контент, ARIA и оформление |
| --- | --- |
| Закрыт | `details.open=false`, `aria-expanded=false`, `data-accordion-state="closed"`; ответ скрыт нативно, иконка «+», вопрос приглушён |
| Hover | На fine pointer закрытый вопрос и иконка меняют цвет; фон карточки сохраняется |
| Focus | Видимый контур на `summary`; Tab перемещает фокус, Enter/Space переключают ответ |
| Открывается | `open=true`, `aria-expanded=true`, состояние `opening`; высота панели от 0 до её содержимого, opacity 0→1 |
| Открыт | Состояние `open`; вопрос основного цвета, иконка повёрнута на −45°, естественная высота ответа |
| Закрывается | `aria-expanded=false`, состояние `closing`; панель уменьшается до 0 и исчезает, иконка возвращается к «+»; `open` снимается после анимации |

Раскрытие и закрытие используют нативный Web Animations API. Длительность:
`--accordion-duration` на группе, затем `--motion-duration` страницы,
по умолчанию **300ms**. Кривая — `--motion-easing`, по умолчанию
`cubic-bezier(0.22, 1, 0.36, 1)`. Поворот иконки задаётся CSS компонента.
Повторный клик отменяет текущую анимацию и запускает новое переключение.
В single-режиме предыдущий пункт закрывается одновременно с открытием нового;
во время перехода оба могут временно иметь `open`, после завершения открыт один.

Не фиксировать высоту ответа и не скрывать содержимое через произвольный
`max-height`. После перехода высота остаётся естественной и реагирует на
изменение ширины/контента. Цветовые переходы используют `--transition-site`.

При `prefers-reduced-motion: reduce` JS сразу переключает состояние,
CSS-переходы практически мгновенные. Если Web Animations API недоступен,
раскрытие также работает без анимации. Без JS работает нативный `details`:
ответы доступны с клавиатуры, несколько пунктов могут быть открыты одновременно.
Ограничение single относится к JS-enhancement.

## Владение состоянием и cleanup

Источник истины — `details.open`. Shared JS синхронизирует `aria-expanded` и
`data-accordion-state`; проект не должен переключать эти значения независимо.
`data-accordion-initialized` — диагностическая отметка, не дополнительный hook.
Публичных custom events у FAQ нет.

Повторное выполнение `components.js` вызывает `window.__academyComponentsCleanup()`:
снимает listeners, отменяет анимации и удаляет служебные состояния. Затем
инициализация заново читает нативный `open`. Этот cleanup относится ко всем
Academy-компонентам страницы, включая CTA и sliders, а не только к FAQ.
При динамической замене DOM использовать полный цикл cleanup → вставка →
повторная инициализация; не добавлять вторую копию обработчика FAQ.

## Оформление и адаптив

Цвета и шрифт наследуют Academy role tokens. `--faq-divider-color` управляет
рамкой/разделителями, `--radius-card` — скруглением, `--color-focus` — focus.
`faq_list` задаёт `--accordion-item-gap: 0`. Внешнюю ширину, тексты и реальные
варианты заголовка/описания оставлять проекту.

Вопрос и ответ используют fluid width и intrinsic height. Базовые padding
20px, от 768px — 24px. Минимальная высота вопроса — 72px, от 768px — 74px;
иконка занимает отдельную колонку и не сжимается. Размер вопроса — fluid
18–24px, заголовка секции — 36–52px. На мобильном hover не требуется для работы.

## Передача в Tilda

HEAD: встроить используемые `components.css` и тему страницы. BODY: разместить
семантическую разметку FAQ с утверждённым контентом. FOOTER: встроить
`components.js` один раз после разметки. Сборщик проекта владеет generated
фрагментами; не оставлять runtime-пути `../../shared/` в production.

Контакт поддержки и возможные SEO-данные FAQ принадлежат лендингу. Не копировать
чужой адрес, schema или ответы и не создавать JSON-LD автоматически по наличию
компонента. Нативные формы Tilda, CAPTCHA и CRM не являются зависимостями FAQ.

## Адаптивная композиция эталона

`renderFaq(data, {id = 'faq'})` из `faq-render.mjs` собирает цельный блок;
`faq-responsive.css` включается через `faq_component.is-responsive` поверх
существующего FAQ. Legacy FAQ без этого варианта сохраняет прежние стили.
Данные: `heading`, необязательные `supportText`, `supportButton`, `supportAction`,
`items[{question, answer: string[]}]`. Текст экранируется, NBSP сохраняется.
Для нескольких экземпляров нужны разные ID. Все ответы по умолчанию закрыты.
Назначение поддержки подключает проект через `data-action`; пока его нет,
действие остаётся фокусируемой preview-кнопкой `aria-disabled`.

| Параметр, px | ≤520 | 521–767 | 768–1024 | ≥1025 |
| --- | --- | --- | --- | --- |
| H2 / подзаголовок | 32 / 16 | 36 / 18 | 44 / 20 | 52 / 22 |
| Заголовок → подзаголовок | 20 | 20 | 24 | 28 |
| Шапка → список | 32 | 36 | 42 | 70 |
| Вопрос / ответ | 20 / 15 | 22 / 16 | 24 / 18 | 24 / 20 |
| Поля сверху/по бокам и под ответом | 16 | 20 | 24 | 24 |
| Вопрос → ответ | 16 | 16 | 16 | 16 |
| Абзацы ответа | 4 | 8 | 8 | 8 |
| Плюс / крест | 28 | 28 | 32 | 32 |

Все размеры в CSS — rem. Вопрос использует общий
`content-heading_component.is-card`, ответ — общий `body-text_component`,
шапка — `section-header_component.is-responsive`. Нижнее поле summary — 16px
в обоих состояниях, чтобы расстояние до ответа не меняло высоту summary при
анимации; между текстом вопроса и иконкой 32px. Граница и разделители — 0.3px,
радиус 16px. Высота вопросов/ответов растёт по содержимому.

Иконка — отдельный [плюс/крест](toggle-icon.md), общий с будущими компонентами.
Подключать `toggle-icon.css`, `faq-responsive.css`, `body-text.css`,
`section-spacing.css` и последним `section-heading.css` вместе с базовыми
`components.css` / `components.js`. В Tilda встроить все CSS и SVG mask.
`faq_support-action` владеет общими hover/focus/pointer, проект — точечной
защитой цвета от Tilda. Поведение accordion, keyboard, no-JS, reduced motion,
single-open, 300ms и cleanup остаются описанными выше.

## Проверка

Открыть через локальный сервер [стенд](tests/faq-fixture.html). Он использует
реальные `faq.html`, `components.css` и `components.js`: проверяет состояния,
длительность анимаций, закрытие предыдущего ответа, повторный клик, независимые
группы и повторную инициализацию. Параметр `?motion=reduce` проверяет мгновенную
ветку JS, `?js=off` — нативную работу без enhancement.

Перед передачей также проверить Enter/Space/Tab, видимый focus, hover,
overflow на 375/768/1024/1440px и обе стороны 767/768px, длинные ответы,
отсутствие JS-ошибок и фактические HEAD/BODY/FOOTER лендинга.
Проверять реальную промежуточную высоту/opacity и завершение анимации, включая
быстрый повторный клик. Проверка конечного `open` не подтверждает плавность.
Принудительный `?motion=reduce` принадлежит только этому тестовому стенду;
обычное превью лендинга не должно менять системный media query по URL.
