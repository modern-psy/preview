# Semantic HTML and accessibility

Обязательный минимум для структуры, интерактивности и ручной проверки лендингов.
Цель — WCAG 2.2 AA; автоматический аудит дополняет, но не заменяет ручной.

## Native semantics first

- Сначала выбирать подходящий HTML-элемент; ARIA добавлять, только когда нативной
  семантики недостаточно.
- `<a href>` ведёт в другое место, `<button type="button">` выполняет действие.
  Не имитировать их через интерактивные `div`/`span`.
- На странице один `<main>`; повторяющиеся header, navigation и footer находятся
  вне него.
- `<nav>` используется для крупных навигационных групп и получает accessible name,
  если таких групп несколько.
- `<section>` имеет смысловую тему и обычно заголовок. Если темы нет, использовать
  `<div>`.
- `<article>` содержит самостоятельный материал, `<aside>` — связанный, но не
  основной контент.
- Последовательности оформляются `ul`/`ol`, табличные данные — `table`, пары термин
  и определение — `dl`.

## Document and reading order

- Один ясный `h1` обозначает главную тему страницы; последующие уровни отражают
  структуру, а не визуальный размер.
- Внешний вид заголовка задаётся `heading-style-*`, семантический тег не меняется
  ради размера.
- DOM order остаётся понятным без CSS и совпадает с логикой чтения и Tab order.
- Язык документа задаётся через `lang`; фрагмент на другом языке получает свой
  `lang`.
- Текст ссылки понятен вне абзаца; повторяющееся «подробнее» получает контекст.

SEO-метаданные, canonical, Open Graph и правила изображений находятся в
[`seo.md`](seo.md).

## Keyboard and focus

- Все действия доступны с клавиатуры в естественном DOM order.
- Положительный `tabindex` не использовать. `tabindex="0"` нужен редко,
  `tabindex="-1"` — для программного focus.
- Видимый `:focus-visible` нельзя удалять без равноценной замены.
- Escape закрывает modal/popover и возвращает focus логичному инициатору.
- Стрелки реализуются только для паттернов, где они входят в keyboard contract.
- Modal намеренно удерживает focus; остальные компоненты не создают keyboard trap.
- Длинная повторяющаяся навигация получает skip link к `#main-content`.

## Forms

- Каждый control имеет видимый `<label>`; placeholder его не заменяет.
- Используются корректные `type`, `name`, `autocomplete`, `inputmode` и связанные
  подсказки.
- Ошибка объясняется текстом, связывается с полем и объявляется assistive
  technology; цвет не является единственным сигналом.
- После неуспешной отправки focus или error summary ведёт к проблемам без потери
  введённых данных.
- Обязательность сообщается визуально и программно.
- Submit остаётся настоящей кнопкой; loading state не уничтожает accessible name.

## ARIA and dynamic content

- ARIA не добавляет поведение автоматически: keyboard и focus реализуются отдельно,
  если нет подходящего native control.
- Accessible name предпочтительно берётся из видимого текста. `aria-label`
  используется, например, для icon-only button.
- `aria-expanded`, `aria-controls`, `aria-current`, `aria-pressed` и
  `aria-invalid` меняются вместе с фактическим состоянием.
- Live region сообщает только важные динамические изменения.
- Все ARIA-referenced ID уникальны, включая несколько экземпляров компонента.
- Скрытый контент не оставляет доступных по Tab интерактивных элементов.

## Media, visual state, and motion

- Значимые изображения получают контекстный `alt`, декоративные — `alt=""`.
  Сложная схема имеет краткую альтернативу и полное текстовое объяснение.
- Видео с речью требует captions; важная визуальная информация — текстовой
  альтернативы или audio description по контексту. Autoplay со звуком запрещён.
- Цвет, изображение или анимация не являются единственным носителем смысла.
- Контролы имеют различимые hover, focus, active, disabled и error states.
- Контент остаётся функциональным при 200% zoom, крупном пользовательском шрифте и
  узком viewport.
- Текст, который должен читаться, переводиться или индексироваться, не запекается
  в растровое изображение.
- `prefers-reduced-motion` сохраняет смысл, состояние и функцию; essential content
  никогда не остаётся скрытым из-за сбоя анимации.

## Verification

1. Отключить CSS: структура и reading order остаются понятными.
2. Отключить JavaScript: основной текст и навигация доступны, где возможно.
3. Пройти страницу клавиатурой вперёд и назад.
4. Проверить focus, skip link, overlays, формы и error recovery.
5. Проверить accessible names, roles и states в accessibility tree.
6. Проверить alt, headings, landmarks, уникальные ID и `lang`.
7. Проверить 200% zoom, крупный системный шрифт и узкий viewport.
8. Проверить `prefers-reduced-motion`.
9. Запустить автоматический аудит и вручную разобрать предупреждения.
10. Для ключевого шаблона выполнить smoke test экранным диктором.

Страница или компонент не готовы, если основное действие недоступно без мыши,
состояние не объявляется или смысл зависит только от изображения, цвета или motion.
