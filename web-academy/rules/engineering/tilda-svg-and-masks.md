# SVG и маски при переносе в Tilda

Обязательный стандарт для локальных SVG, CSS masks и декоративных изображений,
которые сборщик переносит в Tilda через HEAD и T123. Правило дополняет
[`components.md`](components.md), семантическую доступность и проектный asset
registry.
Общие правила посекционной упаковки, идентификаторов, popup и вертикального
ритма находятся в [tilda-delivery.md](tilda-delivery.md).

## Источник и способ доставки

- Канонический SVG хранится в `projects/<slug>/assets/` и изменяется только в
  source. Сгенерированные `tilda/*.html` вручную не редактируются.
- Production-фрагменты не содержат `localhost`, repository-relative `assets/`
  или `shared/`. Использовать постоянный Tilda CDN URL, встроенный data URL или
  оправданный inline `<svg>`.
- Выбирать один render contract до сборки:
  - meaningful image — `<img>` с размерами и контекстным `alt` либо доступный
    inline `<svg>`;
  - decoration/icon — `aria-hidden="true"`, пустой `alt` у `<img>`, CSS
    background, mask, pseudo-element или семантически нейтральный `<span>`;
  - SVG, которым управляют через DOM, paths или CSS variables, остаётся inline;
    не превращать его в background только ради уменьшения BODY.
- Base64 предпочтителен для SVG внутри CSS: он не требует отдельно экранировать
  `#`, кавычки, пробелы и переносы. Percent-encoded SVG допустим только после
  проверки корректного URL-encoding.

## Локальные растровые изображения

Решение пользователя от 2026-09-16. Локальные `assets/*.webp`, `.png`, `.jpg`
в production-фрагменты не встраиваются по умолчанию, даже если файл меньше
16 000 байт. Для каждого изображения запрашивается постоянная CDN-ссылка
(Tilda) и подставляется в `src`/`poster` исходного `index.html`.

- Сборщик обязан остановиться и перечислить каждый локальный растровый файл
  без ссылки. Это алерт для оператора, а не предупреждение в логе.
- Временный обход только для проверки сборки: флаг `--allow-local-webp`.
  Даже с флагом каждый встроенный файл выводится в stderr отдельной строкой.
- Пакет, собранный с флагом, не считается готовым к переносу в Tilda, пока
  список не пуст.

## Replaced elements и прозрачная заглушка

`<img>` является replaced element: содержимое `src` рисуется поверх его CSS
background. Поэтому непрозрачный пиксель скрывает вынесенный SVG и выглядит в
Tilda как белый квадрат, засветка или «шакальная» схема.

- Для чисто декоративной CSS-графики по возможности использовать `<span>` или
  pseudo-element вместо `<img>`.
- Если `<img>` нужно сохранить ради стабильной геометрии или T123-контракта,
  builder заменяет его локальный `src` только на проверенный полностью
  прозрачный placeholder, а видимый SVG помещает в page-scoped CSS background.
- Название `transparent` или префикс `data:image/gif;base64` ничего не
  гарантируют. GIF обязан содержать Graphic Control Extension с включённым
  transparency flag; PNG/WebP/SVG должен декодироваться с alpha `0` в пикселе.
- Сохранять `width`, `height`, CSS-размер, aspect ratio, классы, `alt`,
  `aria-hidden` и `draggable`. Заглушка не должна менять layout или доступность.
- Нельзя использовать непрозрачную белую/чёрную заглушку и надеяться, что
  `background-image` окажется выше неё через `z-index`: содержимое `<img>` и его
  background находятся внутри одного paint contract.

Типовой generated contract:

```html
<img
  class="component_icon"
  src="{{ verified-transparent-placeholder }}"
  width="24"
  height="24"
  alt=""
  aria-hidden="true"
>
```

```css
.project-page .component_icon {
  background: url("data:image/svg+xml;base64,...") center / contain no-repeat;
}
```

## CSS masks

- Mask задаёт только alpha-форму. Элементу всё равно нужны явные intrinsic
  dimensions и видимый `background-color`, обычно `currentColor`.
- Для Tilda/WebKit объявлять обе версии: `-webkit-mask-*` и стандартные
  `mask-*`; фиксировать `position`, `size` и `repeat`.
- Mask URL должен быть self-contained или постоянным production URL. Не
  оставлять относительный путь внутри CSS custom property.
- Не использовать mask для meaningful image: она не несёт `alt` и не заменяет
  доступное имя.
- Проверять active, muted, hover, focus, disabled, error и success variants:
  Tilda может переопределить `color`, а значит и `currentColor` маски.

```css
.project-page .component_mask {
  width: 1.5rem;
  height: 1.5rem;
  background-color: currentColor;
  -webkit-mask: url("data:image/svg+xml;base64,...") center / contain no-repeat;
  mask: url("data:image/svg+xml;base64,...") center / contain no-repeat;
}
```

## HEAD/BODY и лимит T123

- Большой или повторяющийся SVG не дублировать в BODY. Builder может оставить
  компактный прозрачный `src`, а единственный data URL перенести в CSS внутри
  HEAD.
- Для переноса в Tilda каждая содержательная секция страницы собирается в
  отдельный BODY-файл и отдельный блок T123. Не объединять несколько секций в
  один BODY-файл, даже когда общий размер укладывается в лимит.
- Числовой префикс получают только файлы содержательных BODY-секций. Нумерация
  начинается с `01-` и следует порядку секций на странице; HEAD, STYLE,
  вспомогательные BODY-данные и FOOTER нумеровать не требуется. Использовать
  префиксы фиксированной ширины (`01-`, `02-`, …), чтобы алфавитная сортировка
  BODY-файлов совпадала с порядком переноса.
- Каждый BODY-файл начинается с отдельной строки с понятным HTML-комментарием:
  `<!-- Секция 01: Название секции -->`. Номер в комментарии отражает порядок
  секции на странице, а название позволяет определить содержимое без открытия
  preview. Имя BODY-файла также содержит короткое смысловое название секции,
  например `01-body-hero.html` или `07-body-program.html`.
- BODY-разметка должна быть читаемой: структурные элементы оформляются с
  переносами строк и отступами по вложенности. Проверять лимит T123 после такого
  форматирования; не минифицировать BODY в одну строку ради экономии символов.
- BODY и HEAD после такого преобразования являются одной версией компонента.
  Переносить и откатывать их только парой; смешивание разных сборок возвращает
  пустые изображения, белые квадраты или старую графику.
- Selector в HEAD и placeholder-элемент в BODY образуют проверяемый контракт.
  Builder должен падать, если обязательный SVG отсутствует, selector потерян
  или локальный путь остался в production-фрагменте.
- Считать длину окончательно отформатированного BODY через `body.length`, а не
  размер файла в bytes. Если проект не задаёт более строгий бюджет, держать
  защитный порог ниже `65 000` characters.
- Generated BODY вручную не переформатировать перед вставкой: сборщик уже
  создаёт канонические переносы и учитывает их при проверке лимита.
- Экспортный wrapper каждой секции обязан сбросить page-level геометрию через
  `min-height: 0; height: auto`. Нельзя повторять `min-height: 100vh` в каждом
  T123: высоты складываются и создают кратные пустые промежутки.
- Внешние поля T123 равны нулю. Отступами владеет только section spacing
  component; wrapper, пустой spacer и T123 не добавляют параллельные слои.

## Защита от каскада Tilda

- Generated defaults для SVG/span не должны перебивать состояния компонентов.
  Если требуется общий `display:inline-block`, весь selector помещать в `:where()`
  с нулевой специфичностью; page prefix вне `:where()` повышает приоритет.
  Сохранять hooks, классы и hidden-состояния при преобразовании img в span.
- Проверять не только статичные иконки, но и idle/error/success формы после
  сборки: idle скрывает оба значка, остальные состояния показывают ровно один.
- Tilda может добавлять глобальные `!important` для `a`, `button` и состояний
  controls. Защищать только authored semantic color внутри уникального page
  root, например `.project-page a.button.is-accent`.
- Не применять широкое `.project-page a, .project-page button { color: inherit
  !important; }`: оно ломает light/accent/dark variants и hover states.
- Вложенные кнопки библиотек также входят в проверку: код страны intl-tel-input
  наследует цвет кнопки выбора страны. Защищать semantic color на конкретном
  control, не маскировать дефект удалением конфликтующего тестового правила.
- Если base color защищён через `!important`, все намеренно отличающиеся
  `:hover`, `:focus-visible`, `:visited`, `disabled`, error/success colors также
  получают точечное page-scoped правило нужной специфичности.
- `!important` здесь является документированной Tilda-protection boundary, а не
  обычным способом повышать специфичность компонентов.

## Обязательная проверка

- Собрать пакет дважды и подтвердить одинаковые manifest hashes, затем запустить
  project Tilda tests.
- Автоматически проверить отсутствие local URLs, лимит BODY, наличие каждого
  обязательного data URL и парность HEAD/BODY contract.
- Для transparent placeholder проверять декодированную прозрачность или форматный
  transparency flag, а не только строку base64. Сохранять regression check на
  известную непрозрачную заглушку, если она уже вызывала дефект.
- В локальном preview собрать реальные generated HEAD + BODY. Дополнительно
  имитировать конфликтующее Tilda `!important` для ссылок и кнопок.
- Визуально проверить каждую SVG/mask variant на светлом и тёмном фоне: крупные
  схемы, стрелки, form error/success, hover/focus и disabled. Белый квадрат,
  сплошная заливка или исчезнувший background считается блокирующей ошибкой.
- Повторить smoke test через фактический Tilda copy/paste path на 375, 768, 1024
  и 1440px; проверить console/network и опубликованную страницу, потому что T123
  внутри редактора работает не полностью.
