# Web components

Практический стандарт повторно используемых компонентов для лендингов Web
Academy. Он применяется вместе с Client-First, семантическим HTML и правилами
переноса в Tilda.

Платформенная база — [Web Components по MDN](web-components-mdn.md), выбранная
пользователем как стандарт. Перед проектированием компонента читать карту
концепций и правила применения к секции; при работе с Custom Elements, Shadow
DOM, slots, events или ElementInternals — соответствующие разделы и точные
ссылки API. Не заменять этот стандарт механическим копированием учебных примеров.

## Эталон для следующих проектов

По решению пользователя «Психолог-консультант»
(`projects/psychologist-consultant/`) — базовый проект для компонентной
архитектуры всех следующих лендингов Academy. Каждую его секцию последовательно
оформлять как переиспользуемый компонент с полным адаптивом, состояниями и
поведением по передаваемым пользователем материалам.

Это прямое поручение извлекать компоненты проекта в общую библиотеку. Эталоном
конкретной секции считать её реализацию после сверки с переданными адаптивами
и проверки; существующий код ещё не переработанных секций не считать
автоматически утверждённым. Общие исходники и публичные контракты хранить в
`shared/academy/`, а проект использовать как эталон их интеграции. Контент,
медиа, назначения действий и коммерческие условия остаются данными лендинга.

Передаваемую пользователем базу знаний HTML/CSS сохранять в долгосрочных
правилах репозитория по соответствующей теме; компонентные правила — здесь.
Не ограничиваться контекстом чата или записями в `STATE.md`.

## Общий адаптив и радиусы

Обязательная основа текущих и следующих компонентов —
[общая система отступов](../../shared/academy/spacing.md),
[responsive.md](../../shared/academy/responsive.md) и его JSON-контракт.
Планшет: 768–1024px включительно; desktop: от 1025px. Согласовывать CSS и JS
по этой границе и проверять собранные исходники через `assertResponsiveContract`.
Радиусы карточек брать из [card-spacing.md](../../shared/academy/card-spacing.md):
12px на обоих мобильных адаптивах, 16px от планшета. Особые шкалы, например
превью лекций, принадлежат контракту своего общего компонента.

### Обязательные роли при переиспользовании

- Внутренние поля тёмной секции, включая тарифы, задаёт общий
  [section-spacing.is-inset](../../shared/academy/section-spacing.md).
  Не смешивать `--section-inset-space` с внешним межсекционным `--section-space`.
- Основные кнопки переносить вместе с [button_component](../../shared/academy/button.md),
  включая адаптивные боковые поля белого варианта. Эта геометрия должна жить
  в Shared, а не в теме первого лендинга-потребителя.
- Для новых Hero с текстом слева и объектом фотографии справа применять
  [subject-right](../../shared/academy/hero.md#медиа-состояния-и-tilda).
  Проверять положение главного объекта в каждом адаптиве; координаты фокуса
  конкретной фотографии принадлежат лендингу.
- Составная секция [историй изменений](../../shared/academy/practice-stories.md)
  использует карточки Reviews и поведение референсного `dialogue`: одна колонка
  до 520px, сетка 2+2+1 на 521–767px и горизонтальное движение на широких
  экранах по контракту. Не подменять мобильные раскладки горизонтальным
  слайдером и не определять горизонтальный телефон через `orientation`.

## Новый лендинг из общих компонентов

При создании следующего лендинга Academy обязательно использовать
[руководство нового проекта](../../shared/academy/new-landing.md) и
[каталог библиотеки](../../shared/academy/README.md). Перед подключением
выбранного блока читать его текущий контракт и проверять реальные исходники.
Состояние извлечения эталона —
[COMPONENTS.md](../../projects/psychologist-consultant/COMPONENTS.md#готовность-к-переиспользованию);
не считать старый отчёт аудита доказательством текущей готовности.

- Новый лендинг создавать отдельно в `projects/<slug>/`. Подключать общие
  исходники из `shared/academy/`; не импортировать тему, runtime или данные
  другого курса. Эталон показывает интеграцию, а не задаёт содержимое страницы.
- Сначала переиспользовать подходящую цельную секцию вместе с вложенными
  карточками, тегами, контролами, адаптивами и состояниями. Отдельные компоненты
  использовать по их публичным контрактам. Общие CSS/JS не форкать в проект.
- Где есть shared renderer, передавать собственные данные и генерировать HTML
  локально. Где контракт использует HTML-шаблон, брать его и менять проектное
  содержимое. Не создавать новый renderer или Custom Element только ради
  единообразия способов подключения.
- Copy, assets и их реальные размеры, actions, тема, внешние ширины, consent,
  native form marker и получатели принадлежат новому лендингу. Проверять
  захардкоженные пути, ID и метаданные перед переносом выбранного компонента.
- Перед сборкой Tilda применять общий стандарт
  [посекционной передачи](tilda-delivery.md): project-prefixed scroll ID не
  пересекаются с popup hash Tilda, marker формы берётся только из project JSON,
  а каждый секционный wrapper сбрасывает page-level высоту.
- Проектные `render-*.mjs` и сборщик эталона не являются универсальными:
  запуск или импорт может изменить файлы старого курса. Создавать адаптеры
  нового проекта под его состав секций и данные. Generated Tilda-фрагменты
  и ZIP использовать для доставки соответствующей страницы, не как исходники
  библиотеки.
- Итоговый Tilda-пакет встраивает shared CSS/JS и локальные ассеты, сохраняет
  порядок зависимостей и не требует файлов репозитория. Проверять каждый файл,
  включая HEAD, на лимит 65 000 символов; порядок и hashes задаёт manifest.
- Наличие компонента в shared не означает завершённую визуальную приёмку.
  Проверять новый контент, границы адаптивов, состояния и автономный комплект;
  при изменениях общего кода проверять затронутых потребителей. Нерешённые
  проверки сохранять в STATE соответствующего проекта.

Актуальные ограничения компонентов хранить в их контрактах и компонентном
каталоге, обновляя их после извлечения. Не дублировать временный список
недоработок в глобальных правилах. Разрешение на preview/deploy одного курса
не переносится на новый проект.

## Полнота переноса поведения

При извлечении, подключении и исправлении готового компонента обязательны
[правила переиспользования Shared](../../shared/academy/reuse-rules.md).
Они определяют полный состав переноса, владение настройками анимации,
проверку длительностей при сборке и порядок диагностики. Подключение только
HTML/CSS/JS без необходимых настроек темы не считается полным переносом.

## Уровни переиспользования

Выбирать минимальный достаточный уровень:

1. CSS token — одно повторяемое решение: цвет роли, spacing, radius, duration.
2. Global style или utility — типографический или структурный класс.
3. HTML/CSS-компонент — повторяемая структура без собственного lifecycle.
4. Web Component — повторяемое поведение, состояние, события или изоляция.

Статичная карточка, цитата или секция не становится Custom Element только из-за
повторения. Web Component оправдан, если ему нужны единое stateful-поведение в
нескольких местах, lifecycle с cleanup, устойчивый публичный API или реальная
изоляция.

## Базовый выбор для обоснованного Custom Element

Существующий HTML/CSS или progressive-enhancement компонент не требуется
переписывать в Custom Element ради соответствия этому разделу.

- Использовать автономный Custom Element с именем из двух и более частей через
  дефис: `<academy-accordion>` или `<academy-media-player>`.
- Не использовать customized built-in elements из-за неодинаковой поддержки.
- Light DOM является default для контентного лендинга: исходная семантика и
  содержимое остаются доступны, индексируемы и редактируемы до запуска JavaScript.
- Shadow DOM допустим только для действительно изолированного виджета. Решение
  должно описывать причину, public styling API и проверку в Tilda. `closed` Shadow
  DOM не является механизмом безопасности.
- Не регистрировать элемент повторно: перед `customElements.define()` проверять
  `customElements.get()`.

Имена одного компонента образуют предсказуемый контракт:

```text
HTML tag       <academy-accordion>
JavaScript     AcademyAccordion
CSS            accordion_component, accordion_trigger, accordion_panel
behavior hook  data-js="accordion-trigger"
custom event   academy-accordion:change
local token    --accordion-panel-gap
```

Префикс Custom Element и event должен быть достаточно уникальным для общей
страницы Tilda. Переименование CSS-класса не должно ломать поведение или аналитику.

## Контракт компонента

До реализации зафиксировать рядом с компонентом:

- назначение и места использования;
- минимальную семантическую разметку, обязательные и необязательные части;
- attributes/properties, их типы и единственный источник состояния;
- keyboard contract и управление focus;
- наружные custom events;
- semantic tokens и локальные CSS custom properties;
- результат без JavaScript и при `prefers-reduced-motion`;
- cleanup listeners, observers, timers, media и animation instances;
- размещение кода в Tilda: `<head>`, body HTML block или footer.

Необъявленный атрибут, класс или внутренний DOM-узел не считается публичным API.
Внешняя страница управляет размещением компонента, компонент — своей внутренней
компоновкой.

Одинаковая текстовая роль и её адаптивная шкала имеют один общий typography-класс.
Не создавать секционные копии `font-size`, `font-weight` и `line-height` для
одного Body Text. Карточки и секции владеют раскладкой и gap; различия текстовой
роли оформляются явным вариантом общего компонента. Эталон —
[`body-text_component`](../../shared/academy/body-text.md). Разница только
в расстоянии заголовок/описание задаётся параметром общей карточки, а не её копией.

Заголовок стандартной карточки и вопрос FAQ используют одну роль
`content-heading_component.is-card` по [контракту заголовков](../../shared/academy/section-heading.md).
Заголовок секции и группа подзаголовков также остаются общими компонентами;
размеры и интервалы не дублировать в секционных стилях. Утверждённое исключение
Hero на широких экранах сохраняет его существующую fluid-шкалу.

Плюс/крест раскрытия — самостоятельный декоративный
[toggle-icon](../../shared/academy/toggle-icon.md). Переиспользовать его в новых
блоках с таким индикатором, а не рисовать новые линии или добавлять отдельный
обработчик. Native control и accordion владеют состоянием, иконка — только видом.

В списках с молнией иконка всегда стоит напротив первой строки текста на всех
адаптивах, включая многострочные пункты и увеличенный текст. Не выравнивать её
по центру всей высоты абзаца; правило применяется ко всем компонентам с такой
маркировкой (включая бесплатные лекции, диплом и тарифы).

Повторяющиеся контентные карточки используют общие токены внутренних отступов
и промежутков, включая карточки Hero и иллюстрированные карточки. Для Academy
это [card-spacing.css](../../shared/academy/card-spacing.md): `--card-padding`
и `--card-grid-gap`. Наличие описания не создаёт отдельный padding; резервы
под иллюстрации сохраняются по контракту компонента. Не возвращать секционные
копии шкалы отступов при переносе в Tilda.

## Реестр и граница владения

- Общая библиотека хранит рядом с исходниками единый перечень публичных
  компонентов, классов, behavior hooks, variants, fallback без JavaScript и
  Tilda placement. Для Academy это `shared/academy/README.md`.
- Проект документирует собственные составные компоненты в одном проектном
  component catalog. Секционные layouts и интеграционные компоненты не
  переносятся в shared только потому, что проект завершён.
- Перед переносом project-компонента в shared нужен второй реальный consumer
  с совпадающим semantic contract либо прямое поручение пользователя сделать
  компонент общим. Проверять затронутые лендинги и независимое подключение.
  Copy, theme, asset URL, контракт формы и production exceptions остаются у страницы.
- Generated Tilda-фрагменты не являются component source и не включаются в
  реестр как отдельные реализации.

## Обязательные готовые компоненты Academy

По решению пользователя все извлечённые секции эталона переиспользуются целиком,
включая вложенные карточки, теги, типографику, адаптивы, состояния и поведение.
Полный состав, публичные API и ссылки на контракты хранятся только в
[каталоге shared/academy](../../shared/academy/README.md). Выбирать подходящий
компонент там; не собирать готовую секцию заново по внешнему виду.

Новые текст или назначение CTA не создают новый компонент. Общие варианты
дополнять в библиотеке. Тема, внешние колонки, числа, медиа, ссылки/попапы
и аналитика принадлежат странице. Пример в шаблоне не разрешает автоматически
переносить коммерческие условия и получателей другого курса.

CTA и FAQ используют `components.js` один раз на страницу, форма —
`lead-form.js`. Не добавлять второй FAQ handler или отдельный JS на каждый CTA.
Для FAQ с одним открытым ответом сохранять `data-accordion-single`: следующий
ответ открывается с одновременным закрытием предыдущего. Сохранять все состояния,
доступность, no-JS, touch/reduced-motion и cleanup по руководству компонента.

Форму переиспользовать вместе с интеграцией. `data/form-contract.json` и native
блок Tilda владеют mapping, CAPTCHA, получателями и доставкой; локальный success
не доказывает доставку в CRM. Соблюдать [правила Tilda bridge](tilda-form-bridges.md).

При внедрении обновлять component catalog и сборщик лендинга: shared CSS/JS
встраиваются в самодостаточный Tilda-пакет. Generated-фрагменты не редактировать
вручную. При изменении общей реализации проверять потребителей, несколько
экземпляров и сохранение адаптива. Полный реестр —
[shared/academy/README.md](../../shared/academy/README.md).

## Якорная навигация

По поручению пользователя анимация якорных переходов из «Терапии травмы»
вынесена в обязательный общий компонент для следующих лендингов Academy.
«Психолог-консультант» и «Терапия травмы» используют одну реализацию:
`shared/academy/anchor-scroll.css` и `anchor-scroll.js`.

- При наличии ссылок на разделы подключать компонент и ставить
  `data-academy-anchor-scroll` на контейнер ссылок. Сохранять нативные `a href`
  и уникальные ID целей, включая fallback без JavaScript.
- Scroll target использует project-prefixed ID. Hash, настроенный в Tilda как
  popup, не может одновременно быть ID секции; popup-ссылка получает
  `data-tilda-popup-link` и остаётся вне обработки scroll runtime.
- Не возвращать проектные scroll handlers, не заменять компонент глобальным
  `scroll-behavior: smooth` и не применять к навигации duration hover/FAQ/слайдеров.
- Точный контракт анимации, URL/history, focus, прерываний, reduced motion,
  исключений и cleanup хранится только в
  [anchor-scroll.md](../../shared/academy/anchor-scroll.md). Изменять общее
  поведение там и в shared-исходниках, затем проверять обоих потребителей.
- Общий отступ до цели составляет `50px` на мобильных и `100px` с `48rem`, чтобы
  фиксированный хедер Tilda не перекрывал начало секции. Значения принадлежат
  общему публичному token; локальное переопределение допускается только при
  подтверждённой другой высоте хедера.
- Встраивать CSS в Tilda HEAD, JS один раз в FOOTER; переносить opt-in в BODY.
  Проверять актуальный автономный пакет и реальные промежуточные кадры в браузере.
  Автотесты не заменяют визуальную проверку движения. Незавершённую проверку
  фиксировать как текущий blocker в `STATE.md`, а не как успешную приёмку.

## Компонент формы и transport bridge


Видимая форма и мост к нативной Tilda-форме — связанные, но разные контракты:

- HTML/CSS-компонент владеет labels, active fields, validation presentation,
  focus, busy/error/success UI и progressive enhancement;
- project JSON contract владеет точными именами полей, mapping, consent,
  receivers и критериями end-to-end успеха;
- bridge JavaScript только валидирует, зеркалирует данные, вызывает нативный
  submit и коррелирует штатные Tilda events;
- нативная Tilda-форма владеет CAPTCHA, transport, receivers и CRM delivery.

Публичный component catalog обязан ссылаться на project JSON contract и на
[`tilda-form-bridges.md`](tilda-form-bridges.md). Нельзя смешивать UI state с
доказательством доставки: визуальный success не является самостоятельным
transport API.

## Progressive enhancement

Исходный HTML содержит основной текст и нативную семантику. JavaScript улучшает
взаимодействие, но не создаёт единственную доступную версию контента.

```html
<academy-accordion class="accordion_component">
  <details class="accordion_item">
    <summary class="accordion_trigger">Вопрос</summary>
    <div class="accordion_panel">
      <p>Ответ.</p>
    </div>
  </details>
</academy-accordion>
```

Если `<details>/<summary>` закрывают задачу, JavaScript добавляет только нужное
групповое поведение или согласованную анимацию. В кнопочной реализации используется
`<button type="button">`, а `aria-expanded` и `aria-controls` синхронизируются с
фактическим состоянием.

## Lifecycle

- В `constructor()` инициализировать только внутренние поля и, если обосновано,
  Shadow Root.
- Дочернюю разметку читать и поведение подключать в `connectedCallback()`.
- Повторное подключение не создаёт второй listener, observer или animation
  instance.
- В `disconnectedCallback()` освобождать все внешние ресурсы.
- Наблюдаемые атрибуты перечислять в `observedAttributes`, изменения обрабатывать
  в `attributeChangedCallback()` без рекурсивной рассинхронизации.
- Ошибка или отсутствие необязательной части в одном экземпляре не ломает другие.

Приоритет источника истины для состояния:

1. native attribute: `open`, `disabled`, `checked`;
2. ARIA state, когда native-эквивалента нет;
3. `data-state` для внутреннего состояния без первых двух вариантов;
4. `is-*` только как визуальный variant или синхронизированное отражение.

## Стили и Tilda

- Client-First classes остаются CSS API: `accordion_component`,
  `accordion_trigger`, `accordion_panel`.
- JavaScript использует `data-js` или API Custom Element, а не CSS-класс как
  хрупкий hook.
- Компонент использует semantic tokens проекта; локальный публичный token имеет
  префикс компонента, например `--accordion-panel-gap`.
- Не применять глобальные descendant-селекторы, способные захватить вложенный
  компонент.
- Для Shadow DOM документировать только необходимые styling hooks: custom
  properties, `::part` и slots.
- Итоговый HTML/CSS/JS компонента копируется в Tilda самодостаточно и не зависит
  от локального `shared/` или build step.
- Видимый copy внутри компонента следует правилам управляемых переносов из
  [`../product/typography.md`](../product/typography.md); `text-wrap` не заменяет
  `&nbsp;` для тире, коротких служебных слов, дат и величин.
- SVG backgrounds, CSS masks, прозрачные placeholders, лимит T123 и допустимая
  page-scoped `!important`-защита следуют отдельному обязательному стандарту
  [`tilda-svg-and-masks.md`](tilda-svg-and-masks.md).

## Готовность

- [ ] Работает с мышью, клавиатурой и touch.
- [ ] Имеет корректные accessible name, role и state.
- [ ] Основной смысл сохраняется без CSS, контент — без JavaScript, где возможно.
- [ ] Нет keyboard trap; overlay возвращает focus ожидаемому инициатору.
- [ ] Reduced motion сохраняет функцию и конечное состояние.
- [ ] Reconnect/remove не оставляет listeners, observers или animation instances.
- [ ] Несколько экземпляров не конфликтуют по ID и состоянию.
- [ ] Внешний layout не зависит от недокументированных внутренних деталей.
- [ ] Публичный контракт и Tilda placement описаны рядом с компонентом.
