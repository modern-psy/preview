# Форма: использование и настройка в Tilda

## Что редактировать в коде

Тексты, подписи и иконки — `data/lead-form.json`. Имена полей, marker, правовые
ссылки и mapping — `data/form-contract.json`. Разметку генерирует
`render-lead-form.mjs` через общий [компонент](../../shared/academy/lead-form.md).
После правки выполнить `node projects/psychologist-consultant/build-tilda-bundle.mjs`
из корня репозитория. Не редактировать generated HTML вручную.

Для другой страницы использовать собственные данные, уникальные section/form ID,
свои изображения и правовые ссылки. Сохранить API shared-компонента и bridge.
Marker `trauma-therapy` здесь сохранён намеренно для совместимости с уже настроенным
блоком. Он не задаёт адрес отправки. Сам интерфейс не содержит получателя или CRM.

## Что сделать в Tilda

1. Вставить актуальные HEAD, STYLE, BODY и FOOTER по `tilda/README.md` и
   `manifest.json`. Не смешивать файлы разных сборок.
2. Сохранить существующую штатную форму на странице. Для нового лендинга
   дублировать уже настроенный нативный блок, а не создавать его по виду custom UI.
   Расположить блок между последним BODY и первым FOOTER. Не удалять его из DOM:
   bridge скрывает найденный `.t-rec` сам.
3. Проверить поле `tildaspec-formname` со значением `trauma-therapy` и имена:

   | Поле интерфейса | Имя в нативной форме |
   | --- | --- |
   | Имя | `Name` |
   | Почта | `email` |
   | Телефон | `Phone` |
   | MAX / Telegram | `messenger-type` |
   | Контакт в выбранном мессенджере | `messenger-id` |

   Сохранить телефонные маски и служебные поля. В унаследованном блоке MAX
   использует слот `whatsapp`, bridge отправляет значение `max`.
4. В настройках нативной формы выбрать получателей/подключённый сервис и сохранить
   CAPTCHA, если она настроена. Код лендинга эти настройки не создаёт.
5. Проверить ссылки согласия и политики в контракте и интерфейсе. Опубликовать
   страницу и проверить, что native marker найден только у нужного блока.
6. При разрешённой контрольной заявке проверить оба мессенджера: значения
   дошли в нужные поля, неактивный контакт очищен, получатель получил заявку.
   Успех интерфейса должен появляться только после `tildaform:aftersuccess`
   именно отправленной формы. Во время CAPTCHA сохраняется ожидание; ошибка
   оставляет введённые данные и позволяет повторить отправку.

Локальные стенды проверяют состояния и mapping с имитацией транспорта.
Они не подтверждают доставку получателю. В этой работе реальные заявки не отправляются.
