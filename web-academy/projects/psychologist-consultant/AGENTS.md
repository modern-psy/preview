# «Психолог-консультант» — правила проекта

Область: `projects/psychologist-consultant/`. Этот файл дополняет корневой
[AGENTS.md](../../AGENTS.md) и хранит только правила и исключения данного курса.

## Маршрут контекста

1. Прочитать [STATE.md](STATE.md), если он существует: только оставшиеся вопросы.
2. Найти блок в [COMPONENTS.md](COMPONENTS.md); прочитать его shared-контракт
   и нужные записи `data/design-source.json`.
3. Для сборки читать [README.md](README.md#перенос-в-tilda), для проверки —
   [CHECKLIST.md](CHECKLIST.md), для формы — [FORM-TILDA.md](FORM-TILDA.md).

Общие правила — [архитектура](../../rules/engineering/components.md),
[каталог](../../shared/academy/README.md), [новый лендинг](../../shared/academy/new-landing.md).
Не загружать правила других курсов для обычной работы. «Терапия травмы» может
служить техническим примером интеграции, но её контент и исключения не наследуются.

## Источники и редактирование

- Этот лендинг — эталон интеграции общих компонентов Academy. Использовать
  цельные shared-секции с вложенными карточками, типографикой и поведением.
  Не возвращать извлечённые CSS/JS в проектные копии.
- Дизайн и пользовательские уточнения — `data/design-source.json`, медиа —
  `data/assets.json`, действия — `data/actions.json`. Состав секций и их данные —
  [COMPONENTS.md](COMPONENTS.md). Скрытые слои Figma не становятся содержимым курса.
- Shared renderer владеет маркированной областью `index.html`; менять данные
  и исходник renderer, затем запускать проектный adapter. Все адаптеры,
  записывающие `index.html`, выполнять последовательно, actions — после секций.
- Тема и внешняя сетка принадлежат `.psychologist-consultant-page` в `styles.css`;
  общий API `.academy-page` сохраняется. Не дублировать внутренние шкалы в теме.
- Следовать общим [адаптивам](../../shared/academy/responsive.md),
  [отступам и проверке Figma](../../shared/academy/spacing.md),
  [заголовкам](../../shared/academy/section-heading.md),
  [Body Text](../../shared/academy/body-text.md),
  [кнопкам](../../shared/academy/button.md) и
  [радиусам/полям карточек](../../shared/academy/card-spacing.md).
  Подозрительное отличие макета сообщать с секцией, диапазоном, ролью и обоими
  значениями. Подтверждённые пользователем исключения сохранять явно.

## Размерная сетка и Hero

- Поля страницы: 1rem до 767px, 1.5rem на 768–1199px, 5rem от 1200px.
  Отступ Hero от хедера: 2rem на мобильных, 3rem от 768px.
- До 1200px все секции занимают полный контейнер. Суженные 10/12 и 8/12
  действуют только от 1200px; это дополнительная граница внешней сетки,
  не замена общего desktop от 1025px. Программа, таймлайн, команда и лекции —
  10/12; рейтинги — 8/12; диплом и блок после выпуска — 12/12.
- Сетки использовать по доступному месту: Grid/Flex, fr, проценты и max-width.
  Размеры текста и отступы — rem/clamp; width/height изображений описывают файл.
- Hero собирается целиком общим renderer; его fluid-типографика сохраняется.
  Опорная ширина Figma 991px — точка интерполяции, не breakpoint.
  Проверять по [hero-checklist.md](../../shared/academy/hero-checklist.md).
- Медиа брать по существующим URL сайта из реестра. Не заменять их временными
  Figma URL. Готовую обрезку пяти WebP команды сохранять без нового crop.

## Проектные решения по секциям

- Порядок после `#foundation`: `#program` → `#learning` → `#trial-lectures` →
  `#support-team` → `#teachers` → `#diploma` → `#graduation`.
  После тарифов: `#pricing` → `#admission` → `#grant`.
- Программа — статичные карточки этапов. Не возвращать плюсы, раскрытие,
  скрытые ответы и темы другого курса. Два подзаголовка образуют одну общую группу.
- Таймлайн сохраняет согласованную сетку на всех ширинах: не переносить
  альтернативную перестановку из Figma. Шрифты и оформление карточек следуют
  общему контракту. Тексты шагов 2–6 брать из правильных карточек, не повторов portrait.
- Все подписи шагов, включая полную фразу про «Эксперт», используют одну
  типографику. На desktop длинная подпись расширяется влево; её нельзя уменьшать
  ради переносов. Планшетная колонка подписей — 14–16.375rem. Круг выровнен по
  центру первой строки. Конец линии следует отметке 90% высоты viewport;
  сохранять затухание, no-JS и reduced motion общего компонента.
- В practice-path женщина с дипломом прилегает к низу карточки, созвон
  центрируется по высоте рядом с текстом; до 521px оба изображения центрированы
  горизонтально. В CTA foundation сохранять перенос перед «и ответим на ваши вопросы».
- Превью лекций — редактируемые HTML/CSS, не изображение с текстом и не плеер.
  Мобильная рамка, обрезка и затухание принадлежат [trial-lectures](../../shared/academy/trial-lectures.md).
- Диплом — общий компонент с заменяемым изображением и вставками; использовать
  `data/diploma.json` и изображение `asp-diploma` из реестра.
- Академия: заголовок/описание выпускников на portrait — 24/16px.
  Desktop-описания Академии 24px намеренны. Фактический вес 444 названий
  превью лекций принят пользователем. Не превращать их в новые ошибки аудита.
- Остальные применённые решения типографики —
  `data/design-source.json#typography_review_decisions`; действующие размеры
  находятся в shared-контрактах. Незавершённый аудит не является разрешением на правку.

## Преподаватели и отзывы

- Преподаватели — цельный shared `teachers` и отдельный `teacher-card`.
  Состав, порядок, тексты и crop редактируются только в [teachers/data.html](teachers/data.html);
  заголовок и подписи — `data/teachers-section.json`. Табы и карточки используют
  один массив. Непустые теги должностей начинаются с заглавной буквы.
- Геометрия навигации, прозрачные touch targets и край следующей карточки —
  [teachers/README.md](teachers/README.md) и [общий контракт](../../shared/academy/teachers.md).
  Фото закрывает всю медиарамку без светлых краёв; исправлять crop в данных.
  Для отсутствующих портретов разрешены заглушки до передачи фото.
- Отзывы берутся из `data/reviews.json`: пять уникальных авторов, без дублирования
  открытого/закрытого состояния Figma. На всех ширинах работает слайдер; на обоих
  мобильных видна одна карточка, все остальные сохраняются в ленте.
- Размеры и шрифты отзывов следуют первой карточке каждого адаптива. Play,
  pause и close равны высоте «Подробнее» по общему [контракту](../../shared/academy/reviews.md).
  Play и pause белые. Оба MP4 используют существующие CDN URL, без autoplay.
- Сохранять подпись Елены: «Сравнила несколько школ» основным цветом,
  «и выбрала Академию» вторичным. Изображения и порядок принадлежат данным.
- `AcademySliderControls` общий для отзывов и преподавателей. Вертикальная
  прокрутка не двигает слайдер; последняя стрелка выключается на реальном конце
  без пустых кликов. Сохранять focus, Escape, cleanup и независимость экземпляров.

## Действия, форма и анимации

- Одинаковый текст кнопок не означает одно назначение: различать `pricing`,
  `enrollment`, `mini-course`, `trial`. Источник — `data/actions.json`.
  Не придумывать URL. Preview без назначения сохраняет focus и pointer.
- Якоря используют общие `anchor-scroll.css/js` и `data-academy-anchor-scroll`.
  Их анимация независима от общих UI-переходов.
- UI — 150ms ease-in-out через `--motion-duration`, `--motion-easing`,
  `--transition-site`; слайдеры — 400ms через `--slider-duration`, FAQ — 300ms
  через `--accordion-duration`. Проверять промежуточное состояние. Обычный preview
  не подменяет системный reduced motion; искусственные режимы — только в тестовом стенде.
- CTA с сеткой сохраняют общее JS-поведение, cleanup, touch/reduced-motion.
  FAQ использует `data-accordion-single`, общий toggle-icon и accordion runtime.
- Пользователь разрешил совместимость формы с готовым нативным блоком
  «Терапии травмы»: marker/mapping — [data/form-contract.json](data/form-contract.json).
  Это явное исключение для этого курса; не переносить marker на новые лендинги.
- Настройки форм, попапов и получателей Tilda выполняет пользователь.
  Не предполагать конкретную CRM и не отправлять тестовые заявки без поручения.
  Подтверждение пользователя о работе формы не выдавать за проверку доставки агентом.
- Сохранять MAX/Telegram, валидацию активных полей, отключение скрытого контакта,
  invalid/valid и success по shared-контракту формы. Проверять видимость значков
  после SVG → span и цвет кода страны под конфликтующим Tilda `!important`.
  Не исправлять эти состояния широким глобальным `inherit`.

## Разработка и передача

- Production — Tilda. До визуальной реализации выполнить требования локального
  сервера и Browser из корневого AGENTS; проверять актуальный собранный preview.
- `build-tilda-bundle.mjs` владеет `tilda/`. Полная сборка и ZIP обязательны для
  передачи UI-изменений; `--preview-only` их не заменяет.
- Короткий HEAD содержит подключения, стили и встроенные изображения находятся
  в `styles*.html` перед BODY. Порядок берётся из manifest; каждый файл меньше
  65 000 символов. Не резать CSS-правила, секции и JS-модули.
- Общие исходники встраиваются в пакет; runtime не зависит от `shared/`.
  Проверять точный перенос HEAD + STYLE + BODY + FOOTER, ZIP и hashes.
  При передаче указывать только фактически изменившиеся связанные фрагменты.
- По прямому поручению пользователя разрешён существующий Vercel preview
  `psychologist-consultant` для команды. После проверенных UI-изменений обновлять
  его автономным экспортом и сравнивать опубликованный ответ с экспортом.
  Команды — [README.md](README.md#командное-превью-vercel). Не создавать новый проект.
  Изменение только документации не требует пересборки UI или публикации.
