# КПТ Оксфорд — правила проекта

Лендинг «КПТ Оксфорд» хранится только в `projects/cbt-oxford/`.
Корневой [AGENTS.md](../../AGENTS.md) применяется полностью.

## Контекст перед работой

1. Прочитать текущий [STATE.md](STATE.md), когда он существует.
2. Следовать [new-landing.md](../../shared/academy/new-landing.md) и
   [правилам компонентов](../../rules/engineering/components.md).
3. Сопоставить макеты с [каталогом Academy](../../shared/academy/README.md),
   затем читать контракты выбранных секций и вести [COMPONENTS.md](COMPONENTS.md).
4. Перед интеграцией проверить актуальные ограничения в разделе
   [готовности эталона](../psychologist-consultant/COMPONENTS.md#готовность-к-переиспользованию).
   Сверять его с текущим контрактом и исходниками выбранного shared-компонента:
   библиотека продолжает обновляться.

## Переиспользование и владение

- Использовать готовые секции из `shared/academy/` целиком: вложенные карточки,
  кнопки, типографику, адаптивы, состояния и поведение. Не собирать их заново
  по внешнему виду и не копировать общий CSS/JS в исходники лендинга.
- Для компонентов с shared renderer генерировать полную разметку из данных
  проекта через собственный адаптер. Для остальных использовать готовую
  композицию по контракту. Generated-области вручную не редактировать.
- Тексты, коммерческие условия, состав преподавателей, отзывы, медиа и ссылки
  принадлежат этому курсу. Хранить контент и реестры в `data/`, изображения
  и иконки — в `assets/`; соблюдать особые форматы данных выбранных компонентов.
- Тему хранить отдельно от контента в проектном `styles.css`, под корнем
  `.cbt-oxford-page`: публичные токены, поля и внешние контейнеры. Внутреннюю
  геометрию компонентов не дублировать проектными стилями.
- «Психолог-консультант» — пример интеграции. Не импортировать его CSS,
  данные, render-адаптеры или сборщик; не наследовать его даты, цены, лицензии,
  получателей формы, popup hooks, ширины и разрешения на публикацию.
- Новые общие варианты оформлять в shared с проверкой затронутых потребителей.
  Отсутствующий общий блок сначала сверять с макетом и каталогом, затем
  документировать границу его владения в `COMPONENTS.md`.

## Утверждённые решения курса

- Порядок секций, источники данных и варианты компонентов —
  [COMPONENTS.md](COMPONENTS.md); Figma-узлы и решения —
  [data/design-source.json](data/design-source.json). Не восстанавливать их
  по памяти из соседнего лендинга.
- Пользователь поручил самостоятельно делать недостающие адаптивы на основе
  Shared. Применять общие компоненты и текущие контракты; отдельное согласование
  каждого стандартного адаптива не требуется.
- Тёмные секции используют внутренние поля
  [is-inset](../../shared/academy/section-spacing.md), включая тарифы и истории.
  Заголовки, подзаголовки и расстояние до содержимого —
  [общая система отступов](../../shared/academy/spacing.md).
- Hero использует `image.composition: "subject-right"` по
  [контракту Hero](../../shared/academy/hero.md). На адаптивах сохранять человека
  из правой части исходного фото в видимой области. Кнопки Hero и CTA целиком
  используют [button_component](../../shared/academy/button.md), без проектной
  копии его размерной шкалы.
- «Кому подойдёт курс» — переиспользуемый
  [course-audience](../../shared/academy/course-audience.md): меняются тексты
  и количество карточек, по умолчанию используется общее предоставленное фото.
- «Как обучение меняет практику» —
  [practice-stories](../../shared/academy/practice-stories.md): карточки отзывов,
  короткие цитаты без выдуманного полного текста, одна колонка до 520px,
  сетка 2+2+1 на 521–767px и горизонтальное движение по референсу
  «А что, если стать психологом?» от 768px при подходящем viewport.
- Система табов — [showcase-tabs](../../shared/academy/showcase-tabs.md).
  Все пять интерфейсов используют шрифты и размеры иконок первого таба на
  соответствующем адаптиве. Сценарии всех пяти согласованы пользователем;
  их последовательности, единые тайминги, повтор, видимость и reduced motion —
  в shared-контракте showcase-tabs. Табы используют общий tab_component,
  извлечённый из Teachers. Интерфейсы и вложения принадлежат курсу.
- После табов идёт таймлайн программы, затем преподаватели. В таймлайне все
  описания всегда раскрыты; плюсов и переключения раскрытия нет.
- Преподаватели — готовая секция Teachers. Порядок и утверждённые описания
  находятся в `teachers/data.html`: это редактируемый JSON-модуль для Tilda.
  По одному тегу на карточку, максимум два только по отдельной необходимости;
  у Сергея Падве и Дарьи Батищевой тег «Психолог». Фото и данные разрешено
  переиспользовать через [общий каталог](../../shared/academy/teachers-catalog.md).
  Каталог не должен автоматически менять составы уже собранных курсов.
- После преподавателей использовать полные shared-секции диплома, тарифов,
  формы, Academy и FAQ в порядке из COMPONENTS. Даты/стоимости брать из
  `data/pricing.json`: пользовательские уточнения имеют приоритет над Figma.
  Один тариф оформляется общим `is-single`, без проектной копии внутреннего CSS.
- Скролл и Tilda popup используют разные назначения, чтобы Tilda не перехватывала
  переход к секции. «Получить консультацию» ведёт только к
  `#cbt-oxford-form`, «Смотреть программу» — только к
  `#cbt-oxford-program`. «Получить полную программу» открывает только popup
  `#program`, обе кнопки тарифа — только popup `#form`, бесплатные лекции —
  popup `#free-oxford`; popup-ссылки помечаются `data-tilda-popup-link`.
  Секция формы владеет `id="cbt-oxford-form"`, программа —
  `id="cbt-oxford-program"`; внутренний `id="application-form"` сохраняется
  для form bridge. Общий якорный отступ — `50px` на мобильных и `100px` с
  `48rem` по shared-контракту.
- Названия потоков в переключателе тарифов всегда остаются в одну строку.
  Использовать исправленный общий [Pricing](../../shared/academy/pricing.md):
  ширина учитывает полное название, при нехватке места прокручивается только
  переключатель. Не возвращать перенос слов или уменьшение шрифта ради ширины.
- В заголовке тарифов этого лендинга «Оксфордская модель» начинается с новой
  строки. Перенос задан через `\n` в `title` файла `data/pricing.json` и
  обрабатывается shared renderer. Это решение конкретного курса, а не
  обязательный перенос в заголовках других лендингов.
- Форма использует только собственный `data/form-contract.json` и
  [FORM-TILDA.md](FORM-TILDA.md). Получателей соседнего курса не переносить;
  успешную отправку подтверждает только событие соответствующей native Tilda
  формы. Перед передачей и публикацией обязателен
  [анти-регрессионный checklist](TILDA-REGRESSION-CHECKLIST.md). FAQ использует
  общее single-open поведение и пользовательские тексты.
- После пользовательского тестирования замечания по анимациям передавать
  следующему агенту через STATE и контракт затронутого компонента. Не менять согласованные сценарии без отдельного задания.
- О каждой отсутствующей иконке и о повторяющихся иконках сообщать пользователю,
  указывая секции/карточки повторного использования. Текущий перечень —
  [COMPONENTS.md](COMPONENTS.md#иконки). Не подменять отсутствующий glyph похожим
  без объяснения; проверять Shared и точный экспорт макета.

## Источники, реализация и передача

- Визуальный источник — предоставленные для этого лендинга структурированные
  данные Figma Dev Mode. Не придумывать содержание и тему до получения макетов.
- Стек — семантические HTML, CSS и JavaScript с Client-First именованием.
  Общая якорная навигация обязательна; форму подключать с собственным
  `data/form-contract.json` по shared-контракту и правилам Tilda bridge.
- Перед визуальной реализацией запустить локальный сервер из корня репозитория
  и подключить in-app Browser. Использовать `css-components` и
  `ui-ux-pro-max` в соответствии с корневыми правилами.
- Проверять 375/768/1024/1440px и обе стороны затронутых breakpoint, длинный
  контент, focus/hover, клавиатуру, no-JS, reduced motion, overflow, ошибки,
  ассеты и метаданные изображений по корневым правилам.
- Сделать собственный адаптер сборки под выбранные секции. Итоговые
  HEAD/STYLE/BODY/FOOTER для Tilda должны быть автономными, без локальных путей,
  с порядком вставки и manifest; каждый фрагмент — меньше 65 000 символов.
  Проверить фактический путь копирования собранных фрагментов.
- BODY переносить по одному T123 на секцию, с числовым префиксом только у BODY
  и русским комментарием с номером/названием в начале. Каждый экспортный корень
  `[data-cbt-part]` обязан иметь `min-height: 0`, иначе базовый full-page
  `min-height: 100vh` создаёт ложные кратные межсекционные отступы в Tilda.
- Production-хост — Tilda. Пользователь уже разрешил создание и обновление
  [Vercel preview](https://cbt-oxford-preview.vercel.app) для этого курса;
  повторное подтверждение обычного обновления не требуется. Публиковать только
  автономную сборку в отдельный проект `gleb-projects-work/cbt-oxford-preview`
  по [README](README.md#обновление-vercel), не через корневую `.vercel`-привязку.
  Это разрешение не распространяется на другие лендинги или хостинги.
