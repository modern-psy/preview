# Ошибки переноса в Tilda и защита от повторения

Этот файл — обязательный preflight перед заменой фрагментов и публикацией
лендинга «КПТ Оксфорд». Подробный контракт формы находится в
[FORM-TILDA.md](FORM-TILDA.md), общий стандарт — в
[tilda-delivery.md](../../rules/engineering/tilda-delivery.md) и
[tilda-form-bridges.md](../../rules/engineering/tilda-form-bridges.md).

## Зафиксированные ошибки

| Наблюдавшийся симптом | Причина | Обязательная защита |
| --- | --- | --- |
| «Получить консультацию» открывала popup вместо прокрутки | Скролл-ссылка использовала служебный popup hash `#form` | Для прокрутки использовать только `#cbt-oxford-form`; `#form` оставлять только popup-ссылкам с `data-tilda-popup-link` |
| «Смотреть программу» открывала popup | ID секции совпадал с popup hash `#program` | Секция и скролл-ссылка используют `#cbt-oxford-program`; `#program` принадлежит только popup полной программы |
| Popup-кнопка дополнительно прокручивала страницу | На странице существовала секция с тем же ID, что у popup | На странице запрещены секции `id="form"`, `id="program"` и `id="free-oxford"` |
| Нативная форма Tilda оставалась видимой рядом с кастомной | Значение `data-tilda-form-name` не совпадало с опубликованным `tildaspec-formname`, поэтому bridge не нашёл служебную форму | Сверять marker в опубликованном DOM, хранить его в `data/form-contract.json` и скрывать только `.t-rec` найденной формы |
| Между секциями появлялись пустые экраны высотой в один или несколько viewport | Каждый отдельный T123 получал корень с базовым `min-height: 100vh` | Каждый экспортный `.cbt-oxford-page[data-cbt-part]` получает `min-height: 0` |
| Текст фиолетовой кнопки становился тёмным в Tilda | Глобальные стили Tilda переопределяли цвет текста ссылки-кнопки | Проектный accent selector фиксирует светлый текст с необходимой приоритетностью |

## Выпускной контроль

Сборка не считается готовой к публикации, пока не выполнены все пункты:

1. Сборочные тесты подтверждают отдельные scroll-only и popup-only назначения,
   уникальные ID секций, адаптивный anchor offset, сброс `min-height` и цвет
   accent-кнопок.
2. В опубликованном DOM существует ровно одна нативная `form.t-form` с marker
   из `data/form-contract.json`; marker проверяется по hidden input
   `tildaspec-formname`, а не по названию блока в редакторе.
3. Найденная нативная форма остаётся в DOM, а скрыт только содержащий её
   `.t-rec`. У записи присутствуют `hidden`, `aria-hidden="true"` и
   `data-academy-native-form-record`.
4. Видима ровно одна пользовательская форма — кастомная форма курса. Она не
   находится внутри скрытой нативной `.t-rec`.
5. После загрузки и после поздней инициализации Tilda нативная запись не
   появляется снова: discovery через `MutationObserver` находит её и скрывает.
6. Обе ветки контакта проходят штатную нативную валидацию и CAPTCHA. Success
   показывается только после события той же нативной формы.
7. Получение заявки подтверждено в реально настроенном получателе. Локальный
   preview и визуально успешный экран этого не доказывают.

Текущий подтверждённый marker опубликованной страницы — `trauma-therapy`.
Это только идентификатор формы на этой странице и не разрешение копировать
получателей одноимённого курса. При изменении marker нативный блок Tilda,
`data/form-contract.json` и новая сборка обновляются как одна операция.
