# Site components

Общая библиотека проверенных компонентов для новых сайтов и лендингов в
`apps/preview/`. Сейчас публичных компонентов нет: каталог намеренно создан
пустым, чтобы контракты появлялись вместе с реальными повторными применениями.

## Когда компонент попадает сюда

Первая реализация остаётся внутри проекта в `../web-academy/projects/<slug>/`.
Перенос в эту библиотеку допустим, когда появился второй реальный consumer,
совпадает семантический контракт и обе страницы повторно проверены. Текст,
ассеты, URL, формы, аналитика и production-исключения остаются у лендинга.

## Будущая структура

```text
site-components/
  component-name/
    README.md       # публичный контракт и инструкция использования
    demo.html       # минимальный автономный пример
    component.css
    component.js    # только если компоненту нужно поведение
    tests/          # контрактные проверки при необходимости
```

README каждого компонента фиксирует:

- назначение, семантическую HTML-разметку и обязательные части;
- публичные классы, `data-js` hooks, attributes/properties и custom events;
- keyboard/focus contract, no-JS fallback и reduced-motion поведение;
- semantic tokens и публичные CSS custom properties;
- lifecycle и cleanup внешних ресурсов;
- точное размещение HTML, CSS и JavaScript в Tilda.

Custom Element нужен только для состояния или lifecycle, которые нельзя надёжно
выразить семантическим HTML и CSS. Light DOM и progressive enhancement являются
исходным выбором. Итоговая поставка всегда самодостаточна: лендинг копирует
необходимый код и не загружает файлы из этой директории во время выполнения.

## Реестр

Когда появятся компоненты, канонический каталог хранится в JSON. TOON может быть
сгенерирован только для однородного реестра и только если он заметно компактнее;
он не редактируется вручную. Такой реестр необходимо добавить в manifest
`../web-academy/docs/memory/registries.json`.
