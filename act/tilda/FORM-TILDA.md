# Нативная форма ACT

Источник конфигурации — projects/act/data/form-contract.json. На modern-psy.ru/act 14.10.2026 подтверждены marker `act`, форма form1084768151 и record rec1084768151; получатели подключены. ID указаны только для поиска в редакторе. Bridge ищет по точному hidden `tildaspec-formname=act`, а не по ID.

1. Сохранить существующий нативный блок ACT с его получателями/CRM, CAPTCHA и служебными полями. Удаляется только прежняя видимая обёртка, если она отдельная; сам form block должен остаться в DOM.
2. В этом же блоке добавить обязательное поле «Электронная почта», тип Email, имя переменной `Email`. На исходной опубликованной странице его нет. Без него bridge блокирует отправку и сохраняет введённые данные.
3. Сохранить поля `Name`, `Phone`, `messenger-type` и `messenger-id`. Telegram использует значение `telegram`, штатный MAX — `max_messenger`. Телефонные result/ISO и штатные маски должны остаться; вручную их не переименовывать.
4. Hidden marker `tildaspec-formname` должен равняться `act` ровно в одной нативной форме страницы. Не копировать этот marker в попап бесплатных лекций.
5. Разместить нативный блок после 14-body-lead.html, до footer-form.html. После загрузки bridge скрывает только его ближайшую .t-rec, оставляя настоящую форму активной.
6. Опубликовать и проверить поля в DOM, совпадение marker, обе ветки мессенджера и получение заявок у настроенного получателя.

Кастомное `name` → `Name`; `email` → `Email`; `phone` → `Phone`; выбранный мессенджер → `messenger-type`; только активный контакт → `messenger-id`. Предыдущая ветка очищается. Никаких прямых запросов в CRM и копирования ключей формы в пакет нет.

Попап бесплатных лекций: сохранить #free-lessons-act, record rec2371427761 и marker free-psy0. Его transport и выдачу доступа пакет не подменяет.
