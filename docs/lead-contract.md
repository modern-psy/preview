# Контракт заявки

Черновик от 16.11.2026. Что форма на сайте Astro отправляет вместе с заявкой
и как это ложится в amoCRM. Нужен, когда у сайта появится свой сервер заявок
вместо нативных форм Тильды. Пока прод на Тильде, заявки идут как раньше.

Код, который собирает заявку: `src/scripts/lead/transport.js` (функция `buildLead`).
Режим отправки на весь сайт: `src/data/site.json` → `lead.mode`.

---

## 1. Откуда берутся поля

**Задаём руками,** когда ставим форму на страницу (компонент `LeadForm`, раздел `lead`
в данных страницы):

| Поле | Что это | Пример |
|---|---|---|
| `form` | имя формы; пока прод на Тильде — то же, что имя нативной формы | `ORKT` |
| `intent` | тип заявки (список ниже) | `course` |
| `course` | slug курса в CMS | `orkt` |
| `stream` | дата потока, если форма про конкретный поток | `2027-03-01` |
| `tariff` | тариф, если на странице выбирают тариф | `full` |
| `placement` | где на странице форма | `signup` |

**Форма добавляет сама:**

| Поле | Откуда |
|---|---|
| `contact.name`, `contact.phone`, `contact.email` | из полей формы; телефон в формате +79123456789 |
| `contact.messenger`, `contact.messengerContact` | выбранный мессенджер и ник в Telegram (для MAX — телефон) |
| `source` | название программы для менеджеров, как сейчас в `form_source` |
| `page.url`, `page.path`, `page.title` | адрес и заголовок страницы, где оставили заявку |
| `attribution.utm` | `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term` |
| `attribution.yclid`, `attribution.gclid` | метки кликов Директа и Google |
| `attribution.landing`, `attribution.referrer` | первая страница визита и откуда пришли |
| `ids.ymClientId` | номер посетителя Метрики (кука `_ym_uid`), чтобы связать заявку с визитом |
| `ids.calltouchSessionId` | сессия Calltouch, если скрипт Calltouch есть на странице |
| `device` | телефон, планшет или компьютер |
| `sentAt` | время отправки |

Метки рекламы запоминаются при первом входе на сайт и живут до закрытия вкладки:
человек может оставить заявку через несколько страниц, когда в адресе меток уже нет.

## 2. Типы заявок (`intent`)

| Значение | Что это |
|---|---|
| `course` | запись на курс |
| `waitlist` | лист ожидания курса |
| `booking` | бронь места на следующий поток |
| `free-lectures` | бесплатные лекции курса |
| `access` | доступ к мини-курсу на почту |
| `webinar` | запись на вебинар (запасная форма, если BotHelp не загрузился) |
| `question` | вопрос без записи |

## 4. Как это ложится в amoCRM (предложение)

Сейчас сделка называется «Заявка с сайта https://modern-psy.ru/kpt»: адрес страницы
читается, но выглядит как технический мусор. Предложение:

- **Название сделки** — по-человечески из типа заявки и курса:
  «Запись на курс: ОРКТ · поток 1 марта», «Бесплатные лекции: КПТ. Модель Бека»,
  «Лист ожидания: Корпоративное консультирование».
  Название курса сервер берёт из CMS по `course`.
- **Страница** — отдельным полем `page.url`. По нему по-прежнему видно, откуда заявка.
- **Теги** — `intent` и `course`: по ним удобно фильтровать.
- **Воронка и этап** — по `intent`: запись на курс и бесплатные лекции могут идти в разные воронки.
- **Источник** — `source`, как сейчас `form_source`.
- **UTM, yclid, ymClientId** — в те же поля сделки, что заполняет нынешняя интеграция Тильды,
  чтобы отчёты не разъехались.
- **Контакт** — имя, телефон, почта, ник в Telegram; дубли контакта склеиваются по телефону.

Названия полей и воронки нужно сверить с тем, кто настраивает amoCRM: в аккаунте уже есть
поля, которые заполняет Тильда, и новые лучше не плодить.

## 5. Режимы отправки (`lead.mode` в `src/data/site.json`)

| Режим | Где | Что происходит |
|---|---|---|
| `stub` | превью и зеркало | заявка никуда не уходит; человек видит «Заявка принята» и пометку «тестовая копия» |
| `messengers` | авария, Тильда недоступна | вместо отправки просим написать в Telegram приёмной комиссии |
| `api` | свой сервер заявок | POST на `lead.endpoint` с телом из раздела 3 |

На Тильде (пакеты T123) этого слоя нет: форма отправляет заявку в нативную форму Тильды,
как раньше.
