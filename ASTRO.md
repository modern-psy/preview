# Превью на Astro — пилот

Ветка `astro`, 16.11.2026. Пока это пилот на отдельном тестовом приложении Timeweb:
нынешнее превью (ветка `main`) он не трогает.

## Что внутри

| Где | Что |
|---|---|
| `src/pages/` | новые страницы. Адрес = имя файла: `orkt.astro` → `/orkt` |
| `src/components/` | общие блоки: `PriceBlock` (цена из CMS), `PriceLd` (микроразметка курса), `Faq` (вопросы и FAQPage из одних данных), `LeadForm` (форма заявки) |
| `src/components/<адрес>/` | блоки конкретной страницы, перенесённые со старой вёрстки |
| `src/data/pages/<адрес>.json` | заголовок, описание, вопросы, тексты формы страницы |
| `src/data/site.json` | общие настройки: куда уходят заявки (`lead.mode`) |
| `src/data/redirects.json` | переадресации: 160 старых адресов Тильды и старые имена папок превью |
| `src/layouts/PageLayout.astro` | каркас страницы: `<head>`, noindex, шрифт |
| `tilda-export/` | временные страницы из экспорта Тильды, пока их не переверстали на v1 |
| `docs/lead-contract.md` | что форма отправляет с заявкой и как это ложится в amoCRM |
| старые папки (`act/`, `academy-base/`, `web-academy/` …) | остаются как были и после сборки отдаются по тем же адресам |

## Что сделано в пилоте

- `/orkt` — курс на v1, разложен на блоки; цена, вопросы и форма заменены общими компонентами.
  Цена рисуется при сборке из CMS и обновляется в браузере, как на Тильде.
- `/webinar-ptsd` — вебинар (бывшая папка `webinar-trauma`, со старого адреса переадресация).
- `/rpp` — временная страница из экспорта Тильды: картинки с CDN Тильды, счётчики, Calltouch
  и чат Jivo вырезаны, формы не отправляют заявки.
- Тексты `/orkt` и `/webinar-ptsd` после сборки совпадают с modern-psy.ru слово в слово.

## Команды

Из корня репозитория (нужен Node 22.23 или новее):

```sh
npm install                 # один раз
npm run dev                 # смотреть у себя: http://localhost:4321
npm run build               # собрать сайт в dist/ (то же делает Timeweb)
npm run legacy-to-astro -- webinar-rodbt webinar-rodbt   # перенести старую страницу превью
npm run import-tilda -- ~/путь/к/экспорту rpp womens-care # взять страницы из экспорта Тильды
npm run price-snapshots -- orkt                           # сохранить запасной снимок цены
```

Положить готовую папку с HTML по-прежнему можно: всё, что лежит в корне репозитория
и не является частью Astro, после сборки отдаётся как есть.

## Тестовое приложение в Timeweb

1. App Platform → «Создать» → Frontend, репозиторий `modern-psy/preview`, **ветка `astro`**.
2. Фреймворк: Astro, если он есть в списке; если нет — «Другой» / статический сайт со сборкой.
3. Команда сборки: `npm run build`. Папка со сборкой: `dist`.
4. Версия Node: 22 или новее (Astro 7 на 20-й не соберётся).
5. Переменные окружения не нужны.
6. Домен — технический, который выдаст Timeweb. Основное превью не трогаем.

Когда пилот устроит: влить ветку `astro` в `main` и в основном приложении превью
поменять команду сборки и папку `dist`.

## Чего пилот ещё не делает

- Переадресации — страницы с мгновенным переходом (meta refresh), а не настоящие 301:
  статический хостинг не умеет 301 без настройки сервера.
- Картинки ещё не в Strapi: в старых страницах и экспорте ссылки на CDN Тильды и S3.
- Общий вид вопросов и форм для всех страниц: пока `Faq` берёт классы страницы (`orkt-faq_…`).
- Сборка пакетов T123 для Тильды из страниц Astro: `scripts/build-tilda.mjs` пока читает старые папки.
- Список черновиков на `/` остаётся как был; главная сайта и `/drafts` — следующий шаг.
